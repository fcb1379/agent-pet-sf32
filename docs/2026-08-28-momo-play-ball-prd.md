## 3. 背景与问题

当前 Momo 已能显示 Agent 状态、播放本地或上位机同步的图片/GIF，并提供木鱼、任务花园等能力。这些功能解决“信息可见”和“成果反馈”，但用户大多数时候仍在观看状态或做单次点击：Momo 对用户连续动作的响应不够明显。

多 GIF 能丰富表情，却不会自动形成互动。继续增加表情资源，会提高传输、存储和仲裁复杂度，但用户仍可能把 Momo 理解为一个动画播放器。

需要一个无需上位机、联网或新增素材，数秒内可理解和完成的本地互动，让用户看到自己的动作改变了物体，也改变了 Momo 的行为。

## 4. 目标用户与使用目标

### 4.1 目标用户

- 已在手表宠物页查看 Agent 状态，希望短暂放松的用户。
- 希望宠物表现出主动回应，而不愿维护饥饿、清洁、金币等长期数值的用户。
- 在离线或未连接上位机时，仍希望使用 Momo 本地陪伴能力的用户。

### 4.2 用户目标

- 我能在宠物页立即看懂“球可以拖动”。
- 我拖动并松开球后，能看到球按动作方向移动。
- Momo 会主动靠近球，并在接触时给出清晰但不打扰的反馈。
- 我可以随时退出，设备不会卡顿，也不会影响 Agent 状态与表情同步。

## 5. 产品目标与成功指标

### 5.1 产品目标

1. 建立 5–15 秒完成一次的“拖动 -> 释放 -> 追逐 -> 接触/停止 -> 空闲”闭环。
2. 证明多 GIF 之外，Momo 可以通过轻量状态机产生可感知的互动行为。
3. 在不修改上位机、不新增协议、不持久化数据的前提下完成真机验证。
4. 保持宠物页原有 Agent 状态、图片/GIF 与页面生命周期可靠性。

### 5.2 MVP 成功指标

- 首次看到页面的测试用户无需文字教程，最多两次尝试可完成拖放。
- 有效拖放后，球运动方向与最近的拖动方向一致，不发生明显跳点或越界。
- Momo 在正常可达场景中会追向球，接触反馈可被观察到。
- 一轮自动结束后无需重启页面即可开始下一轮。
- 真机目标刷新体验不低于 20 FPS，无明显残影。
- 连续 200 轮状态机测试与页面反复进入/退出测试无崩溃、越界或退出后回调。

## 6. 核心概念与状态

### 6.1 核心对象

- **球：** LVGL 基础圆形对象，具有位置、有限速度和运动/静止状态。
- **Momo：** 复用现有宠物对象或占位表现，通过有限位置偏移表达追逐；不要求新 GIF。
- **一轮游戏：** 从用户抓住球开始，到成功接触、球停止或超时结束。

### 6.2 产品状态

| 状态 | 说明 | 允许的主要转移 |
| --- | --- | --- |
| 空闲 | 球停在安全位置，Momo 保持原有待机表现 | 按中球 -> 拖动 |
| 拖动 | 球跟随触点，记录有限历史用于估算释放方向 | 松手 -> 运动；取消/越界 -> 空闲 |
| 运动 | 球按有限速度移动、衰减并在边缘反弹 | 接触 -> 反馈；停止/超时 -> 结束 |
| 追逐 | 与运动并行的 Momo 目标行为，不单独创建线程 | 接触 -> 反馈；更高优先级事件 -> 中止 |
| 反馈 | 短时显示接到球或玩耍成功 | 到时 -> 结束 |
| 结束/复位 | 清理本轮瞬时状态，恢复球和 Momo | 完成 -> 空闲 |
| 中止 | Agent 紧急状态、外部表情、传输、退出等打断 | 清理完成 -> 原有流程或页面退出 |

## 7. 用户场景与流程

### 7.1 正常抛球

1. 用户进入宠物页，在屏幕安全区看到 Momo 和一个简洁圆球。
2. 用户按住球，球进入选中态并跟随触点。
3. 用户向任意安全方向拖动后松手。
4. 球沿最近拖动方向移动，遇到内容边界时反弹并逐渐减速。
5. Momo 朝球当前位置靠近。
6. Momo 与球接触后，球停止并出现短反馈。
7. 数百毫秒后 Momo 与球回到空闲布局，用户可再次操作。

### 7.2 球未被接到

1. 球因衰减停止，或本轮达到超时时间。
2. 页面给出中性复位，不显示失败、扣分或负面情绪。
3. 自动回到空闲状态，允许重试。

### 7.3 被系统状态打断

1. 玩球过程中出现必须优先展示的 Agent `NEEDS_INPUT`/`ERROR`、图片传输状态、外部表情播放或页面退出。
2. 玩球立即进入中止，停止运动与触摸处理。
3. 清理玩球的 timer/瞬时状态和对象引用。
4. 展示原有高优先级状态；返回空闲后用户可重新开始，不恢复被中止的旧轨迹。

### 7.4 无效输入

- 按在球外：不启动玩球，不吞掉页面原有合法交互。
- 轻点球但没有有效拖动：球保持或回到安全位置，不产生高速移动。
- 触点离开可用区域或收到取消事件：结束拖动并以零速度安全复位。
- 屏幕边缘触摸：优先保留产品既有返回手势；球的初始位置和活动范围避开边缘冲突带。

## 8. 功能需求

### FR-1 球的呈现

- 使用基础圆形对象和纯色/边框样式，不使用图片或 GIF。
- 球在深浅背景下均可辨识，触摸命中区可大于可见圆，但不得覆盖 Momo 的主要点击区。
- 初始位置必须位于返回手势冲突带之外。

### FR-2 拖动与释放

- 仅球命中区响应拖动。
- 拖动期间球中心始终限制在内容边界内。
- 释放速度只使用最近有限数量/时间的触点样本，速度有明确上限。
- 不以浮点或未限定差值计算速度；时间 tick 回绕必须安全。

### FR-3 球运动

- 使用确定性的整数或定点计算。
- 以 40–50 ms 周期更新，速度、加速度、位置和累计时间均有上下界。
- 触及内容边界后修正位置并衰减反向速度，不允许持续越界抖动。
- 低于停止阈值或达到超时时间后结束，不允许永久运行。

### FR-4 Momo 追逐与接触

- Momo 以有限速度朝球移动，位置始终在视觉安全区域。
- 碰撞采用有界的矩形/圆形近似，不能访问对象边界之外的数据。
- 接触只触发一次反馈；重复 timer tick 不得重复计数或重复创建对象。
- 首版不改变 Momo 资源文件；允许使用现有对象位置偏移、现有可用表情或简单样式反馈。

### FR-5 反馈与复位

- 接触后显示不超过约 1 秒的轻量反馈，例如小幅跳动、短文本或球的样式变化。
- 反馈对象若新增，必须在一轮内复用，不逐次创建。
- 复位后清除速度、触点历史、碰撞锁和超时计数。

### FR-6 优先级与仲裁

- 页面退出的优先级最高，必须同步阻止后续 LVGL 对象访问。
- 图片/GIF 正在提交或切换、外部表情 PLAY/RESTORE、打字场景和关键 Agent 状态不得被玩球遮挡。
- 玩球中止不得修改或回写 Agent 状态，也不得更改图片槽选择。
- 原有木鱼、任务花园等交互不能因透明大面积点击层而误触或失效。

### FR-7 生命周期

- 所有 LVGL 创建、更新和删除只在 GUI/LVGL 线程执行。
- 新增 timer 最多一个，并绑定宠物页生命周期。
- 页面停止时先停止/删除 timer，再清除指针/状态，最后由既有流程删除根对象。
- 退出后任何回调不得引用已删除的球、Momo 或页面对象。

### FR-8 功能开关与回退

- 提供单一编译期开关，关闭时不创建球、不注册玩球事件、不产生新增 timer，原有宠物页行为保持不变。
- 若真机资源、帧率或手势冲突不达标，可关闭功能开关回退，不修改协议或用户数据。

## 9. 范围

### 9.1 本期范围

- 一个内置圆球。
- 单指拖动、释放方向估算。
- 有边界、会衰减和超时的二维运动。
- Momo 追逐、一次接触判定和短反馈。
- 与现有状态/GIF/页面退出的最小仲裁。
- 纯 C 状态机主机测试、目标完整编译、PC 模拟器可用性检查和真机验收清单。

### 9.2 非范围

- 多球、关卡、计分、排行榜、成就和每日任务。
- 商店、金币、食物、道具、物品栏和成长数值。
- 球的图片/GIF/3D/粒子素材、声音、振动或灯效。
- IMU 甩腕投球、双指手势、物理引擎或浮点模拟。
- BLE/USB 新协议、上位机配置、云端同步和跨设备对战。
- 任何持久化；页面退出或设备重启后不恢复一轮游戏。
- 修改现有 GIF 传输格式或要求上位机增加专属表情。

## 10. 验收标准

### 10.1 状态机与主机测试

1. 空闲、拖动、运动、接触反馈、停止/超时、复位和中止均有确定性测试。
2. 零位移、极短/极长拖动、反向拖动、速度上限、四边和四角反弹均不越界。
3. tick 回绕、最大时间步长、异常大坐标输入和重复 release 不导致整数溢出或非法状态。
4. 接触反馈只触发一次；停止和超时均能在有限步数内回到空闲。
5. 连续至少 200 轮随机但有界的输入序列，无断言、越界、死循环或动态内存依赖。
6. 主机测试使用严格警告（至少 `-Wall -Wextra -Werror`）编译通过。

### 10.2 固件集成

7. 功能开关关闭时目标固件完整编译通过，宠物页原有行为和构建产物不依赖新 UI 路径。
8. 功能开关打开时目标 `sf32lb52-lchspi-ulp` 完整编译通过，无新增编译错误；新增警告必须为零。
9. 新增业务状态实测小于 256 B、新增基础 LVGL 对象不超过 5 个、新增 timer 不超过 1 个。
10. 同工具链 A/B 比较的 Flash 增量小于 8 KiB；RAM 增量记录在测试报告中并解释。
11. 不新增线程、协议字段、存储记录或外部素材文件。
12. 图片传输、GIF 切换、外部表情/打字事件和 Agent 高优先级状态可以安全中止或覆盖玩球，不发生对象残留。

### 10.3 PC 模拟器与真机

13. PC 模拟器若可构建，验证拖放、追逐、接触、中止及反复进入/退出；若基线环境不能构建，必须记录真实阻断，不能虚报通过。
14. 240 x 240 真机拖动坐标与触点一致，球中心不会越过内容边界。
15. 球的活动区不抢占既有边缘返回手势；从四边进行返回手势均可正常退出。
16. 运动和追逐期间目标刷新体验不低于 20 FPS，无明显残影、撕裂或连续跳点。
17. 动画中退出、反馈中退出、快速反复进入/退出以及连续玩 200 轮后，无崩溃、无退出后回调、无可观察的持续内存下降。
18. 硬件未实际完成的项目必须标注“待硬件验收”，不得以编译或模拟器代替。

## 11. 资源预算假设

| 资源 | MVP 上限/目标 | 说明 |
| --- | --- | --- |
| 业务状态 | `< 256 B` | 固定结构体，含位置、速度、触点历史、状态、计时与标志 |
| LVGL 对象 | `<= 5` 个 | 球、可选命中层/反馈对象；优先复用现有 Momo 和页面对象 |
| timer | `1` 个，40–50 ms | 游戏状态和 UI 同步使用同一 timer，不新建线程 |
| Flash | `< 8 KiB` 增量 | 以功能开关 A/B 的同工具链构建结果衡量 |
| 外部素材 | `0` | 不新增图片、GIF、音频和字体 |
| 持久化 | `0 B` | 页面退出即结束本轮 |
| 协议 | 无变化 | 不新增 BLE/USB/上位机字段 |
| 性能 | `>= 20 FPS` 体验目标 | 40–50 ms 更新周期；避免全屏不必要重绘 |

这些是进入开发的预算，不是未经测量的完成结论。技术方案和测试报告必须给出实际结构体大小、对象数和 A/B 构建结果。

## 12. 风险与缓解

| 风险 | 影响 | 缓解与门禁 |
| --- | --- | --- |
| 来源无许可证 | 知识产权风险 | Clean-room、零来源素材/代码、独立参数与最终审查 |
| 边缘返回手势与拖球冲突 | 用户无法退出或误投 | 设置边缘保留区、球初始位置避边、真机四边验收 |
| 触摸采样抖动或事件丢失 | 球跳变、高速飞出 | 有界样本、速度钳制、取消事件和最大时间步 |
| 整数溢出/tick 回绕 | 越界、死循环 | 定点范围设计、差值钳制、回绕测试、有限步结束 |
| timer/对象生命周期错误 | 退出后崩溃 | GUI 线程唯一所有者、stop 顺序、回调空指针/状态防护 |
| 与 GIF/图片/Agent 状态争抢 | 关键信息被遮挡 | 明确优先级，高优先级事件中止玩球且不自动恢复旧轨迹 |
| 高频重绘影响 GIF 或 BLE | 卡顿、丢帧 | 单 timer、局部 invalidate、对象数上限、真机帧率和传输并发测试 |
| Momo 位移破坏现有布局 | 文字遮挡或残影 | 限制追逐区域、复位到原始坐标、复用现有对象而非重建 |
| 体验过于机械 | 陪伴感不足 | 保留短反馈；先验证因果清晰，再决定是否另立表情/音效需求 |

## 13. 可行性结论与分阶段建议

### 13.1 可行性

结论为 **可行**：目标项目已有 240 x 240 LVGL 宠物页、触摸事件、周期 timer、Momo 对象、GIF/Agent 状态仲裁基础和 PC 模拟器入口。MVP 可被拆成与 LVGL 无关的固定内存状态机，以及只在 GUI 线程工作的薄 UI 适配层，不需要联网、上位机或新硬件。

关键前提是：技术方案先定义坐标、tick、速度和状态边界；集成层明确页面退出与高优先级状态的中止顺序；最终以真机而非仅编译验证触摸和残影。

### 13.2 交付顺序

1. 先提交实现方案：模块/接口、状态机、坐标和定点范围、LVGL 生命周期、仲裁、预算、回退及测试矩阵。
2. 实现纯 C 状态机与严格主机测试。
3. 接入宠物页基础球对象和触摸事件。
4. 接入 Momo 追逐、碰撞反馈和状态仲裁。
5. 完成功能开关 A/B 目标构建、可用模拟器自测及测试记录。
6. 推送独立分支供成员进行 240 x 240 真机验收；不直接合并默认分支。

## 14. 上位机与兼容性说明

- 本 MVP **不需要上位机处理**，也不修改多 GIF 传输协议。
- 上位机继续按现有逻辑同步表情；当高优先级外部表情到达时，固件负责中止玩球并展示该表情。
- 未来若希望为“接到球”配置专属 GIF，应另立兼容需求，在不要求新协议的前提下评估复用现有槽位；不纳入本期验收。
- 关闭功能开关或不进入宠物页时，设备和上位机行为与基线一致。
