# “摸摸 Momo”连续抚摸互动 PRD

## 1. 来源、版本与原创边界

- 产品灵感证据：[Kz0514/virtual_pet](https://github.com/Kz0514/virtual_pet) 的公开提交 [`55b88d59555335ff679d398c632f49a0346b6d27`](https://github.com/Kz0514/virtual_pet/commit/55b88d59555335ff679d398c632f49a0346b6d27)，committer 时间 `2026-08-13T16:00:13Z`。该提交包含持续摸头反馈等宠物交互。
- 来源仓库标注 Apache-2.0，但 README 同时说明其 VPET 形象/动画受额外授权约束。目标项目只吸收“持续抚摸时宠物持续回应”这一通用产品思想。
- 本 PRD 针对目标的 390 × 490 触屏、192 × 192 宠物舞台、LVGL 页面生命周期、Agent 覆盖、多 GIF 和图片同步重新定义交互。
- **不得复制**来源的代码、GPIO/电极设计、轮询周期、阈值、状态机、文字、VPET 形象、帧动画、音频、字体、布局、服务端或其他素材。MVP 不新增外部素材。

## 2. 问题与目标用户

### 问题

默认分支的 Momo 能接收短击和 IMU 动作；尚未合入默认分支的多状态行为又定义了长按、连击、Agent/时间状态切换。两者的触摸仍是离散命令：用户手指持续停留或轻柔移动时，宠物不会连续“感知”主人。一次点击更像按钮，难以形成“正在摸一只宠物”的身体互动感。

### 目标用户

- 希望设备提供轻量陪伴反馈，而不只是 Agent 状态看板的用户。
- 已经上传多个 GIF，或只使用内置 mascot，也希望触摸行为一致的用户。
- 会把设备放在桌面，随手摸一下宠物、但不希望误触打开其他功能的用户。

## 3. 产品目标与成功指标

- 让用户在宠物头部区域持续按住或轻柔移动时，Momo 在 150 ms 内给出最小视觉反馈。
- 将“按下 → 识别抚摸 → 持续反馈 → 松手恢复”做成完整、可解释、可复现的闭环。
- 不改变默认分支的短击、木鱼、Agent 状态、任务花园、图片/GIF 传输及上位机显式播放语义；集成多状态行为分支后也不改变其长按/连击语义。
- 无专用 GIF、无网络、无音频、无震动时仍可完整验收。
- 目标误触率：100 次普通短击/快速划过中误触发抚摸不超过 2 次；100 次符合轨迹的抚摸成功识别不少于 95 次。真机结果必须记录，不以模拟器代替。

## 4. 创意描述

### 核心体验

用户在 Momo 头部热区按下并轻柔停留或缓慢往返，宠物进入“被摸摸”短时反应：轻微缩放/上下浮动、暖色光晕和“好舒服～”短标签。手指移动时反馈保持；松手并经过短防抖后恢复当时应显示的自主/Agent/远端状态，而不是重置为默认状态。

### 无素材最小反馈

- mascot 以 98%～102% 的轻微缩放或 2～4 px 的缓动位移回应。
- 显示最多 1 个短标签和 1 个半透明光晕，不新增图片、GIF、字体或音频。
- 若以后提供版本化 `petting` 角色 GIF，可替代上述视觉层；MVP 不把 0～4 匿名槽位硬编码成抚摸角色。

## 5. 场景与流程

### 场景 A：停留抚摸

1. 用户在宠物舞台的头部热区按下。
2. 手指在热区内停留至少 650 ms，累计移动不超过 12 px。
3. 系统进入抚摸状态并显示最小反馈。
4. 用户松手；连续 150 ms 无触摸后退出，恢复当前有效视觉状态。

### 场景 B：轻柔往返

1. 用户在头部热区按下。
2. 按下至少 350 ms，累计轨迹 12～160 px；任一 100 ms 窗口移动不超过 80 px，且至少 70% 采样点位于热区。
3. 系统进入并保持抚摸状态；轨迹继续满足条件时不重复创建动画或累计奖励。
4. 松手 150 ms 或离开热区超过 250 ms后退出。

### 场景 C：普通点击/快速划过

- 释放时未达到停留或轨迹门槛：不进入抚摸，继续交给现有短击语义。
- 快速穿越、明显甩动或从舞台外开始：不进入抚摸，也不改变亲密度。

### 场景 D：高优先级事件到来

- 抚摸期间出现 Agent Error/Needs input、任务完成、上位机 `PLAY(slot)`、打字场景、图片/GIF 传输或页面退出时，按优先级安全让出视觉控制权。
- 让出后仍按触摸释放完成内部收尾，但不得抢回画面；高优先级结束后读取最新状态恢复。

## 6. 热区与判定规则

### 头部热区

- 基于现有 `stage` 的局部坐标，而非屏幕绝对坐标，适应布局移动。
- 默认矩形：`x = 20%～80%`、`y = 5%～50%`，即当前 192 × 192 舞台约为 `x=38～154`、`y=10～96`。
- 热区参数必须是具名常量并支持后续角色配置；不得读取 GIF 像素自动推断头部，也不得针对来源形象硬编码。
- 按下必须始于热区；离开舞台立即取消候选，避免覆盖页面导航。

### 采样与状态

- 使用 LVGL 输入事件/当前活动输入设备获取坐标；最多 10 Hz 记录轨迹，避免 20 ms 高频轮询和不必要刷新。
- 纯判定模型状态：`IDLE → CANDIDATE → STROKING → RELEASING → IDLE`。
- 固定大小轨迹摘要，只保存起点、上一点、累计距离、热区采样计数和时间，不保存完整坐标数组，不动态分配内存。
- 32 位 tick 比较必须支持回绕；页面销毁时无条件清空候选/动画，不保留 LVGL 指针。

### 与长按和手势的冲突

- 在头部热区中，抚摸候选优先于现有长按；只有达到本 PRD 门槛后才消费触摸序列。
- 未达到抚摸门槛的触摸，释放后仍允许现有短击处理；不得同时触发短击和抚摸。
- 头部热区外的长按、短击、木鱼和页面手势保持原语义。
- 一次持续按压只产生一次“抚摸开始”和一次“抚摸结束”，不得按定时器周期重复加亲密度。

## 7. 状态与视觉优先级

从高到低：

1. 页面停止、系统安全状态、闹钟/计时器等必须抢占的顶层事件。
2. 图片/GIF 传输、上位机显式 `PLAY(slot)`、打字场景及其恢复流程。
3. Agent Error、Needs input、Working、Completed 等任务状态。
4. 任务花园领取/木鱼等已有明确交互动画。
5. “摸摸 Momo”短时反应。
6. 多状态自主行为的基础情绪与空闲动画。

规则：

- 图片/GIF 传输忙时不启动抚摸视觉，也不切换 decoder；只保留触摸输入的正常释放，不排队补播。
- 上位机远端覆盖和 Agent 覆盖只接管视图；抚摸不会覆盖其 GIF，也不会重置行为模型。
- 退出抚摸时调用统一“恢复当前有效状态”出口，禁止直接固定切回 0 号槽位、Calm 或内置 mascot。
- 如果后续多状态分支提供行为事件接口，抚摸只发送一个 `STROKE` 事件，由行为模型决定亲密度/Happy；当前匿名 GIF 槽位不得被赋予隐含语义。

## 8. 范围

### MVP 范围

- 头部热区、停留/轨迹判定、释放防抖和误触保护。
- 内置 mascot 与普通静态/GIF 宠物均有最小视觉反馈。
- 与短击、长按、木鱼、Agent、任务、图传、多 GIF/远端播放的优先级与恢复。
- 独立编译开关 `AGENT_PET_USING_STROKE`；关闭后不得改变既有事件路径。
- 本地持久化“抚摸反馈”开关，默认开启；Pet 页面提供可访问的独立开关，不与“体感木鱼”开关混用。
- PC 模拟器支持确定性轨迹输入和视觉回退；硬件验证真实触摸坐标与误触。

### 非范围

- 不增加音频、TTS、震动或音乐队列操作。
- 不常驻麦克风，不联网，不新增手机端命令、BLE 协议或服务端。
- 不复制或随固件分发 VPET/候选项目素材。
- 不做手势机器学习、压力识别、多指触摸或自动头像头部识别。
- 不在 MVP 中新增 `petting.gif` 上传协议或占用现有 0～4 匿名槽位。
- 不承诺真实生物式情感或健康效果。

## 9. 验收标准

### 判定与冲突

- 停留 650 ms、温和轨迹 350 ms 两条正向路径均能独立触发；边界值和 tick 回绕有主机测试。
- 短击、快速划过、舞台外起点、离开舞台、超速移动均不会触发抚摸。
- 一次触摸序列只产生一对开始/结束事件；不与短击/长按重复触发。
- 100 次有效抚摸识别率不少于 95%；100 次短击/划过误触发不超过 2 次，并记录测试手法与原始计数。

### 反馈与恢复

- 达到识别门槛后 150 ms 内出现视觉反馈；松手后 150～300 ms 内结束。
- 无专用 GIF、无网络、音频忙、振动不可用时仍可完整工作。
- `PLAY(slot)`、打字、Agent 四态、任务完成、木鱼、图传开始/结束和页面进出均按优先级恢复，不新增第二个 GIF decoder。
- 远端覆盖结束时恢复最新有效状态，而非抚摸开始前的陈旧快照。

### 稳定性与关闭

- 功能开关关闭或编译关闭时，默认分支的短击/木鱼行为与基线一致；若集成多状态行为分支，其长按/连击也必须保持一致。
- 连续 1,000 次开始/结束、快速进出页面和中途图传无悬空 LVGL timer/object、无持续内存增长、无崩溃。
- 所有 LVGL 创建、删除、样式和动画操作只在 GUI 线程；不新增 RTOS 线程。

### 构建与硬件

- 主机判定测试、PC 模拟器完整构建和目标固件完整构建通过，新增告警为 0。
- 给出实际构建命令、text/data/bss 前后对比和测试记录；真实硬件未执行的项目明确标注“待硬件验收”。
- 当前仓库 `sdk/export.ps1` 缺失；必须先恢复固定子模块后才能满足此条，不能以文档或主机测试替代目标构建。

## 10. 资源预算与假设

- 假设当前触摸驱动能通过 LVGL 提供按下、移动、释放及坐标；如硬件只上报按下/释放，MVP 降级为“头部停留抚摸”，不虚报轨迹能力。
- 判定模型静态 RAM 目标不超过 256 B；不保存轨迹数组，不使用动态内存。
- 代码与只读常量 Flash 增量目标不超过 6 KiB；MVP 素材增量为 0。
- 新增 LVGL 对象最多 1 个标签和 1 个简单光晕；页面存活峰值 LVGL 堆增量目标不超过 2 KiB。
- 轨迹采样不高于 10 Hz；视觉更新不高于现有页面刷新节拍，不创建独立线程。
- 不预加载额外 GIF，不增加 PSRAM decoder/canvas 数量。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 不同 GIF 的头部位置不同 | 用户摸不到预期位置 | 热区相对舞台定义、可配置；MVP 用较宽上半区并做真机可用性测试 |
| 快速划过/页面手势误触 | 破坏原交互 | 起点、时长、累计距离、速度和热区占比联合判定；达到门槛前不消费短击 |
| 与长按重复 | 双重状态/亲密度 | 单一触摸序列所有权；热区抚摸成功后显式抑制长按，失败则回交 |
| 图传时切 decoder | 文件/内存竞争 | 图传忙直接拒绝视觉启动，不排队补播；统一恢复出口 |
| Agent/远端覆盖被抢回 | 状态错误 | 明确优先级；抚摸层从不直接选择远端槽位，恢复时读取最新快照 |
| LVGL 生命周期错误 | 悬空对象、崩溃 | 仅 GUI 线程；对象挂在页面 root 下；页面停止时取消动画并清状态 |
| 外部素材版权 | 分发风险 | MVP 零新增素材；只用目标自有 mascot/样式，不复制 VPET 内容 |
| 当前 SDK 缺失 | 无法真实构建 | 恢复固定子模块与工具链后再开发；门禁未通过不得标记完成 |

## 12. 可行性、优先级与交付物

- 可行性：**有条件可行**。现有 LVGL 触屏、pet stage、模拟器和固定内存 C 模型足以实现；需要真机确认移动坐标质量。
- 优先级：**P1**。比新增一个被动页面更能提升宠物差异化，工作量和资源风险较低。
- 当前阻塞：`sdk` 子模块未检出，嵌入式实现和目标构建必须等待固定版本 SDK 恢复授权/配置。
- 产品完成标志：本 PRD 与扫描记录的 Git 文档提交哈希。
- 后续嵌入式交付必须依次包含：实现方案 commit、开发/测试 commit、实际构建命令与结果、资源差异及真机待验收清单。
