# Agent Quest Garden（任务花园）PRD

## 文档信息

- 日期：2026-08-06
- 优先级：P1，建议进入技术方案与小步实现
- 目标版本：首个可验证 MVP
- 依赖：现有 Agent Pet BLE v1 快照、LVGL v8、RT-Thread、`share_prefs`、PC 模拟器
- 灵感声明：产品机制受公开项目的自主环境反应和日结持久化启发；实现必须独立设计，不复制第三方代码、素材、角色、名称、剧情或参数。

## 问题与机会

当前 Momo 能准确显示 Agent 是否运行、等待输入、完成或出错，但体验主要是“读状态”。状态消失后没有轻量成果记忆，用户也缺少一次明确而安全的庆祝动作。传统喂养属性又会制造维护负担，并与大量电子宠物同质化。

机会是利用设备已经收到的最小化、只读 Agent 状态，构造一个不泄露任务内容、不控制远端任务的正向闭环：**Agent 完成真实任务 -> 宠物带回种子 -> 用户点击收下 -> 今日花园成长 -> 次日保留连续成果。**

## 目标用户

- 使用 Codex/Agent 执行开发任务，同时把 SF32LB525 放在桌面或佩戴的开发者。
- 希望不用频繁切回电脑，也能感知工作进展并获得轻量正反馈的人。
- 重视本地隐私，不希望把任务正文、路径、命令或授权内容显示在外设上的人。

## 核心场景与流程

### 场景 A：完成一项任务

1. 某个已见任务从非 `COMPLETED` 状态首次转为 `COMPLETED`。
2. Momo 进入 1.5 至 2.5 秒“带回种子”庆祝态，出现 `Seed ready` 和今日计数。
3. 用户点击宠物，确认收下种子。
4. 花园增加一片叶，显示 `Today n / 5`；达到 5 时当天开花。
5. 重复收到同一任务的 `COMPLETED` 快照不再生成种子。

### 场景 B：用户未及时点击

1. 种子保持待领取标记，不阻塞 Agent 状态刷新。
2. 后续完成事件进入固定小队列；队列满时以饱和计数合并，不动态分配内存。
3. 重启后仍可领取已经持久化的待领取数量。

### 场景 C：跨日回顾

1. 日期变化时结算上一天是否至少领取 1 颗种子。
2. 有成果则连续天数加 1；无成果则归零，但花园不“死亡”、不惩罚用户。
3. 新一天清空当日叶片，保留连续天数；首次进入显示 2 秒昨日小结。

### 场景 D：错误、等待输入或断线

- `ERROR` 只改变宠物即时表情，不扣叶片。
- `NEEDS_INPUT` / 待授权继续使用现有状态提示，不把点击种子误作授权。
- BLE 断线不生成或删除种子；界面明确显示离线。

## 产品规则

- 完成事件键：`task_hash` + 本地最近状态；只有“已见的同一任务从非完成进入完成”计一次。
- 冷启动首次看到 `COMPLETED`：默认不计，避免把历史快照误当新完成；先建立基线。
- 每日展示上限：5 片叶；超过 5 的完成仍累加“今日完成数”，但画面不继续增加对象。
- 待领取队列：最多 8，超过后饱和为 8 并记录溢出诊断计数；禁止 `malloc/free`。
- 去重缓存：固定 12 个会话，与协议最大会话数一致。
- 任务哈希只用于去重和显示稳定性，不作为安全身份，不跨设备同步。
- 点击领取是本地 UI 操作，绝不能调用批准、拒绝、完成任务或执行命令接口。

## 范围

MVP 包含：

- 从现有只读快照识别新的完成转换。
- 固定内存的去重、待领取与当日统计状态机。
- 由 LVGL 基本对象绘制的盆、茎、最多 5 片叶和一朵花。
- 点击领取、完成庆祝、当日计数、连续有成果天数。
- `share_prefs` 持久化：日期、今日完成数、今日领取数、待领取数、连续天数和版本。
- PC 模拟器确定性事件序列与日志。

## 非范围

- 不增加 BLE 写回，不批准/拒绝 Agent 操作。
- 不显示任务正文、路径、命令、用户名或授权内容。
- 不做商店、货币、喂食、清洁、生病、死亡或复杂进化树。
- 不接入 Wi-Fi、云端、排行榜、账号体系或跨设备同步。
- 不新增第三方图片、音频、字体或 GPL 代码。
- 不升级 LVGL v8，不改变默认分支，不修改手机协议。

## 可测验收标准

1. 在 PC 模拟器中，对同一任务注入 `RUNNING -> COMPLETED`，待领取数恰好增加 1，出现庆祝态。
2. 连续注入 10 次相同 `COMPLETED`，计数仍只增加 1。
3. 同一任务 `COMPLETED -> RUNNING -> COMPLETED` 可再增加 1，且规则在文档和测试中一致。
4. 冷启动首帧为 `COMPLETED` 时只建立基线，不增加计数。
5. 点击一次只领取一颗；领取后叶片与 `Today n / 5` 同步更新，不触发任何 BLE 写操作。
6. 五次领取后只创建一朵花，LVGL 对象数不随后续完成无限增长。
7. `ERROR`、`NEEDS_INPUT`、待授权和断线不会扣除、领取或重复生成种子。
8. 保存后销毁并重建宠物页面，今日数据和待领取数保持一致；无效/旧版本存储使用安全默认值。
9. 模拟日期前进：有领取则 streak +1，无领取则归零；不会出现负数、回绕或宠物死亡。
10. 连续运行模拟器 30 分钟并循环 200 次状态变更，无崩溃、无明显对象泄漏、退出页面后 timer/animation 均释放。
11. 固件为 `sf32lb52-lchspi-ulp` 真实构建成功；记录 Flash/RAM 增量和全部警告。
12. 240 x 240 真机上文字不截断、点击区域不遮挡返回手势、动画无残影；未完成真机验证时必须标为“待硬件验收”。

## 资源预算假设

- 静态 RAM：新增业务状态不超过 512 B；不使用动态业务分配。
- LVGL：新增常驻对象不超过 12 个，新增 timer 不超过 2 个；复用现有根对象生命周期。
- Flash：新增代码与常量目标不超过 16 KiB；首版新增素材为 0 B。
- 持久化：单个版本化记录不超过 64 B；状态改变时合并写入，禁止动画帧级写 Flash。
- 性能：日常刷新周期不快于现有状态 timer；庆祝动画目标 20 FPS 以上，不要求全屏持续重绘。
- 显示：以 240 x 240 为唯一 MVP 布局基线。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 重复/乱序快照造成刷分 | 数据失真 | 每会话保存最近状态；重复完成幂等；加入序列测试 |
| 冷启动历史完成误计 | 数据失真 | 首帧完成只建基线 |
| `task_hash` 碰撞 | 极低概率误去重 | 仅做短期 UI 去重，不承担安全决策；缓存随会话槽更新 |
| 误导用户以为点击完成了远端操作 | 安全/信任 | 文案只用 `Collect`/`Seed`；代码层禁止 BLE 写回 |
| Flash 频繁写入 | 寿命 | 只在领取、跨日、页面退出等离散事件写入 |
| UI 对象/动画泄漏 | 稳定性 | 所有 timer/animation 绑定页面生命周期并做 200 循环测试 |
| RAM 基线已较高 | 构建失败/运行风险 | 无新位图、固定数组、记录构建前后 map/size |
| RTC 未同步或回拨 | 连续天数错误 | 未知日期不结算；回拨不重复结算并打诊断日志 |

## 可行性与依赖分析

- 协议已提供 `COMPLETED`、`task_hash`、连接与 generation，输入足够，不需要改 BLE v1。
- `app_pet.c` 已有状态刷新 timer、点击事件、动画和 `share_prefs` 日期持久化，可小步扩展。
- PC 模拟器已有 mock BLE/服务路径，适合先构造状态序列。
- LVGL v8 基本对象足以绘制花园，避免新增版权素材和图片 Flash 成本。
- 最大不确定性是快照槽在任务消失/复用时的语义，技术方案必须先明确槽匹配与去重缓存更新规则。

## 测试矩阵

| 维度 | 用例 |
|---|---|
| 状态 | idle/running/input/completed/error 全转换 |
| 去重 | 重复、乱序、任务消失后重现、12 会话并发、哈希碰撞注入 |
| 连接 | 在线、断线、重连、首帧完成 |
| 存储 | 空记录、有效记录、版本不符、边界值、重启恢复 |
| 时间 | 未同步、正常跨日、跨多日、RTC 回拨 |
| 输入 | 单击、快速连击、无待领取点击、退出时点击 |
| 生命周期 | 反复进入/退出 200 次、动画中退出、timer 回调临界点退出 |
| 显示 | 240 x 240 英文文案、0/1/5/8/饱和计数 |

## 发布与回退

- 先提交技术方案，再实现纯状态机与模拟器测试，最后接 UI/持久化。
- 使用编译期开关或单一入口隔离新功能；关闭时恢复现有 Momo 状态展示和木鱼交互。
- 存储记录带版本；无法解析时忽略花园数据，不影响宠物与 BLE 主功能。
- 任何协议兼容、RAM 或页面生命周期问题无法在预算内解决时，回退为无持久化的“今日完成数”只读提示。

## 优先级结论

建议 P1 落地。该功能对目标仓库有明确独特性，输入已存在、首版无需新增素材或协议，且验收可以先在模拟器完成。只有真实 LCD 触控、残影和资源余量仍需硬件验收。
