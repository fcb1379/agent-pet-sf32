## 3. 背景与问题

Agent Pet v1 已经能在一次快照中接收最多 12 个 Agent 会话。宠物页也会显示总任务数，但当前 `PET_SelectSession()` 只展示活动会话或第一条记录。用户同时运行主 Agent 和多个子 Agent 时，会出现以下问题：

1. 屏幕显示“4 tasks”，但用户看不到其中有几个在运行、等待输入、完成或失败。
2. 当前选中的运行任务可能遮住另一个 `NEEDS_INPUT` 或 `ERROR` 会话。
3. 多个会话连续完成时，只显示一个哈希，用户无法判断是否还有其他结果需要查看。
4. 协议已经付出多会话传输与固定内存成本，设备端却没有兑现其信息价值。

目标不是把 Momo 变成任务管理器，而是让 Momo 像“带队的伙伴”：用户一眼知道小队整体状态，需要时可浏览匿名只读详情，然后回到电脑处理。

## 4. 目标用户与核心价值

### 4.1 目标用户

- 同时运行一个主 Agent 和多个子任务的 Codex/Claude Code 用户。
- 把设备放在桌面，希望不切换窗口即可判断是否需要介入的开发者。
- 只接受最小隐私暴露，不希望任务正文、路径或命令显示在外设上的用户。

### 4.2 用户价值

- **一眼总览：** 在 1 秒内知道运行、等待、完成和错误数量。
- **注意力路由：** 任何 `ERROR` 或 `NEEDS_INPUT` 都不会被普通运行态遮住。
- **保留陪伴感：** Momo 仍是主视觉，多会话只是它带领的“小队状态”，不是大屏表格。
- **零协议扩张：** 利用已有最多 12 会话快照，无需上传敏感文本。

## 5. 产品目标与成功指标

### 5.1 产品目标

1. 把已有多会话快照转换为稳定、可预测、只读的状态摘要。
2. 在不遮挡 Momo 和高优先级提示的前提下，展示最多 5 个代表会话和 `+N`。
3. 让用户能浏览匿名会话详情，但不能在设备端执行 Agent 操作。
4. 不修改 BLE v1 协议、不新增线程/存储/素材，并提供编译期回退。

### 5.2 MVP 成功指标

- 0、1、5、6、12 会话的摘要均无溢出、截断重叠或错误计数。
- 混合状态下首选详情始终遵循 `ERROR > NEEDS_INPUT > 最近完成 > RUNNING > IDLE`。
- `ERROR` 或 `NEEDS_INPUT` 到达后，一个现有 UI 刷新周期内进入首要可见位置。
- 12 会话快照刷新不导致可观察卡顿；Momo/GIF 动画和 BLE 接收保持正常。
- 设备只显示 Provider、短哈希、状态、年龄和统计，不出现任务正文或路径。
- 连续 1,000 次随机合法快照排序测试，以及 200 次页面进入/退出，无崩溃、越界或退出后回调。

## 6. 核心概念与信息架构

### 6.1 小队摘要

底部原状态区显示压缩摘要，例如：

```text
2 running · 1 needs · 1 done
● ● ● ● +3
```

- 状态点颜色沿用目标项目已有状态色，不引入新图标或字体。
- 最多显示 5 个代表会话；其余显示 `+N`。
- 只有一种状态时可简化文案，但计数口径必须一致。
- 断连时保留最后快照，并在摘要前明确显示 `Offline`。

### 6.2 代表会话

- 代表会话由纯 C 视图模型稳定排序，不改变接收快照原始顺序。
- 优先级：`ERROR`、`NEEDS_INPUT`、最近完成、`RUNNING`、`IDLE`。
- 同状态按 `age_seconds` 升序排列；`65535` 视为未知且排在有有效年龄之后。
- 完全相同时保持原快照顺序，避免每次刷新跳动。

### 6.3 只读详情

沿用已有匿名信息，只显示：

- Provider：Agent、Codex 或 Claude。
- `task_hash` 的低 16 位短标识。
- 状态和待授权提示符。
- `age_seconds` 的有限显示，如 `<1m`、`3m`、`unknown`。

首版不得增加任务标题、输入内容、文件名、工作目录、命令、错误正文或审批摘要。

### 6.4 Momo 主视觉

- Momo/GIF 仍占据主视觉区域，并继续由聚合状态驱动动画。
- 多会话状态点只解释“小队”，不为每个 Agent 创建独立 GIF 或宠物实例。
- 关键 `NEEDS_INPUT`/`COMPLETED` 提示层保持最高可见性，小队摘要不得覆盖它。

## 7. 用户场景与流程

### 7.1 多 Agent 正常运行

1. 上位机按现有 BLE v1 下发 4 个会话快照。
2. Momo 保持运行态，底部显示运行/等待/完成计数和代表状态点。
3. 默认详情指向优先级最高的会话。
4. 无用户操作时，详情可按固定节奏轮播代表会话；不得频繁闪烁。

### 7.2 某子 Agent 等待输入

1. 新快照中任一会话变为 `NEEDS_INPUT` 或带 `approval_pending`。
2. 摘要在一次刷新内更新，该会话成为首选详情。
3. Momo 使用既有关注提示表现；设备只提示“需要输入/待授权”，不显示内容，也不提供批准按钮。
4. 用户回到电脑处理，后续快照解除状态后自动回归正常排序。

### 7.3 多会话连续完成

1. 多个会话进入 `COMPLETED`，按年龄由近到远排列。
2. 用户可通过自动轮播或底部独立命中区浏览匿名结果。
3. 完成态退出后从代表列表消失，不在设备持久化“已读”记录。

### 7.4 连接中断

1. BLE 断开后不清除最后有效快照。
2. 页面明确显示 `Offline`，所有详情被解释为历史快照。
3. 重连并收到完整新快照后原子更新，不把新旧会话混合。

### 7.5 页面退出或高优先级表现

1. 页面退出先停止轮播/事件，再删除新增对象和页面对象。
2. 图片提交、GIF 切换、打字场景或既有注意层出现时，小队摘要不得修改其对象或持有其生命周期。
3. 返回普通宠物页后，用最新有效快照重新生成摘要，不恢复旧的瞬时选中动画。

## 8. 功能需求

### FR-1 快照消费

- 仅读取已由 `AGENTPET_ProcessFrame()` 校验并发布的 `AGENTPET_SNAPSHOT`。
- 支持 `session_count=0..12`；不得信任超范围计数或绕过协议层。
- UI 视图模型不得修改快照，也不得以 `task_hash` 作为身份或授权依据。

### FR-2 状态统计

- 对五种合法状态分别计数，并生成有限长度摘要。
- 所有数组索引必须先验证状态和会话数量。
- 文案使用固定缓冲区和 `snprintf`；禁止动态业务内存和不安全字符串函数。

### FR-3 稳定优先级

- 排序规则固定为 `ERROR > NEEDS_INPUT > 最近完成 > RUNNING > IDLE`。
- `approval_pending` 只作为 `NEEDS_INPUT` 内的提示增强，不得改变安全权限。
- 同优先级使用年龄和原始索引稳定排序；不能依赖平台 `qsort` 的不稳定行为。

### FR-4 状态点与 `+N`

- 最多创建 5 个状态点；不足时隐藏复用对象，不反复创建/删除。
- 会话数超过 5 时显示 `+N`；`N` 由有效会话数减去可见数计算，不得下溢。
- 状态点不响应批准、拒绝、重试、停止或打开任务等操作。

### FR-5 详情浏览

- 默认显示最高优先级会话。
- 可使用现有刷新 timer 累积固定周期自动轮播；若增加触摸浏览，只能使用底部明确命中区，并保留边缘返回手势。
- 用户浏览只改变本地选中索引，不写 Flash、不回传 BLE、不改变 Agent 状态。
- 快照变化时若原会话仍存在，可按 `task_hash + provider + source` 尝试保持选择；匹配失败则回到首选会话。该组合仍不是安全身份。

### FR-6 提醒与动画仲裁

- `ERROR`、`NEEDS_INPUT` 和既有 attention panel 高于普通轮播。
- 用户正在查看低优先级详情时，高优先级会话到达应抢占一次；状态解除后才恢复正常轮播。
- 小队雷达不得启动、停止或移动 Momo/GIF 的动画对象。

### FR-7 生命周期与线程

- 所有 LVGL 对象只由 GUI/LVGL 线程创建、更新和删除。
- 优先复用宠物页现有刷新 timer；若技术方案证明必须新增 timer，最多 1 个且必须在 root 删除前停止。
- 页面退出后任何回调不得访问已删除对象；新增对象指针在删除后清空。
- BLE 回调中不得调用 LVGL、排序、格式化文案或阻塞。

### FR-8 功能开关与回退

- 提供单一编译期开关，默认值由技术方案决定。
- 关闭时保持现有 `PET_SelectSession()` 和两行状态展示，不创建新增对象、不执行排序/轮播逻辑。
- 若真机信息密度、触摸冲突或性能不达标，可关闭功能回退，协议和用户数据不受影响。

## 9. 范围与非范围

### 9.1 本期范围

- 0～12 会话的状态统计和稳定排序。
- 最多 5 个状态点、`+N` 和两行有限摘要。
- 自动轮播或底部只读浏览二选一；技术方案应优先选择零新增触摸所有权的方案。
- 断连、空快照、未知年龄和快照更新处理。
- 编译期开关、纯 C 主机测试、目标 A/B 构建、模拟器检查和真机验收清单。

### 9.2 非范围

- 任务标题、正文、目录、文件名、命令、日志、错误正文和用户输入。
- 设备端批准、拒绝、重试、停止、发送消息或控制 Agent。
- 新增 BLE/USB 消息类型、协议 v2、Read/Notify/Indicate 或上位机凭据。
- 为每个会话创建独立宠物、GIF、头像、声音、振动或灯效。
- Provider 筛选页、完整任务列表、搜索、分页、历史记录和已读状态。
- 额度、Token、费用和重置倒计时。
- 持久化会话，或在断连期间推断任务真实状态。

## 10. 验收标准

### 10.1 纯 C 视图模型

1. 0、1、5、6、12 会话输入的计数、可见索引和 `+N` 正确。
2. 五种状态混合时优先级正确，`ERROR` 和 `NEEDS_INPUT` 不会被 `RUNNING` 遮挡。
3. 同状态按有效年龄升序，`65535` 在最后；相同值保持输入顺序。
4. 非法状态、超范围数量和空指针返回明确错误或安全空视图，不越界。
5. 快照替换后保持/失效选中项的行为符合规则，不把哈希当作授权身份。
6. 至少 1,000 组随机合法快照在 `-Wall -Wextra -Werror` 下通过，无动态内存依赖。

### 10.2 固件集成

7. 功能开关关闭时目标固件完整编译通过，现有宠物页行为无功能依赖。
8. 功能开关打开时目标 `sf32lb52-lchspi-ulp` 完整编译通过，新增警告为零。
9. 新增业务状态不超过 128 B，新增常驻 LVGL 对象不超过 8 个，新增 timer 为 0；若最终为 1，必须说明不能复用的原因。
10. 同工具链 A/B 构建的 Flash 增量小于 6 KiB，RAM/BSS 增量有实测记录。
11. 不新增协议字段、线程、存储、外部素材和上位机强依赖。
12. 12 会话快照连续更新时，统计、排序和 UI 更新保持有界；不得在 BLE 回调中执行 GUI 工作。

### 10.3 UI、模拟器与真机

13. 390 x 450 页面在 0、5、12 会话及英文最长固定文案下无重叠、裁切或遮挡 Momo。
14. `ERROR`/`NEEDS_INPUT` 到达后在一次现有刷新周期内成为首选详情，attention panel 仍完整可见。
15. 断连保留最后快照并显示 `Offline`；重连后只显示完整新快照。
16. GIF、JPEG 切换、打字场景、任务花园和体感木鱼不被新增对象或 timer 破坏。
17. 若采用触摸浏览，四边返回手势、底部浏览命中区和未来宠物局部互动不得互相吞事件；若无法证明，回退为自动轮播。
18. 连续 200 次进入/退出和高频快照更新无崩溃、退出后回调或可观察持续内存下降。
19. PC 模拟器若受既有环境阻断，必须记录真实阻断；不能用静态检查冒充模拟器通过。
20. 未执行的 390 x 450 真机项目统一标注“待硬件验收”，编译和主机测试不能替代真机结论。

## 12. 风险与缓解

| 风险 | 影响 | 缓解与门禁 |
| --- | --- | --- |
| 小屏信息过载 | Momo 被任务列表取代 | 只显示摘要、最多 5 点和一条详情；真机最长文案验收 |
| 状态优先级错误 | 需要介入的任务被遮挡 | 独立纯 C 稳定排序、混合状态和抢占测试 |
| 哈希碰撞 | 误以为两个会话相同 | 明确短哈希仅作显示；保持选择时组合 provider/source，仍不用于授权 |
| `COMPLETED` 不是成功语义 | 用户误判结果 | 文案只表达“状态源报告完成”，不承诺业务验收通过 |
| 断连旧数据误导 | 用户把历史快照当实时状态 | 显著 `Offline` 标记；不在设备推断新状态 |
| 触摸与返回/玩球/抚摸冲突 | 页面难退出或事件被吞 | 默认自动轮播；触摸方案须证明独立命中区，否则不启用 |
| LVGL 生命周期错误 | 退出崩溃 | GUI 线程唯一所有者、固定对象复用、退出顺序和 200 次循环测试 |
| 快照频繁更新导致闪烁 | 状态点跳动、用户难读 | 稳定排序、相同视图不重写、保持合法选择 |
| 隐私范围扩张 | 外设泄露敏感任务内容 | v1 字段白名单；禁止任务正文/路径/命令，协议变化需另行安全评审 |
| 与来源表达过近 | 许可证和产品同质化风险 | 独立小屏 Momo 设计，不复制大屏列表、筛选、配色、文案或代码 |

## 13. 可行性结论与优先级

### 13.1 可行性

结论为 **可行，建议进入技术方案和受控 MVP 开发**。

关键依据：

- 目标 `AGENTPET_SNAPSHOT` 已固定支持最多 12 个会话，不需要协议或上位机新增字段。
- 目标页面已经显示会话总数、Provider、短哈希、状态和待授权标志，说明数据和基本文案路径已存在。
- 当前缺口集中在一个固定上限的纯 C 视图模型和小量 LVGL 对象，能够用编译期开关隔离并以 A/B 构建测量。
- 功能保持只读，符合 Agent Pet v1 安全边界；失败时关闭开关即可回退，不涉及数据迁移。

主要不确定性是 390 x 450 真机信息密度，以及后续与抚摸/玩球分支的触摸所有权。技术方案应优先采用自动轮播，先证明摘要价值，再决定是否开放底部浏览触摸。

### 13.2 优先级

- **P1。** 多 Agent 是当前 Codex 工作流的核心场景，协议能力已经存在而 UI 未兑现，用户价值与改造成本比高。
- 优先级高于新增粒子小游戏、通用导航或新的联网设置；这些方向要么与已有功能重复，要么扩大资源和安全面。

### 13.3 交付顺序

1. 先提交实现方案：视图模型、稳定排序、文案上限、LVGL 对象树、生命周期、提醒仲裁、预算和回退。
2. 实现与 LVGL 无关的纯 C 摘要/排序模块和严格主机测试。
3. 接入底部摘要和固定状态点，首版优先零新增触摸。
4. 完成功能开关 A/B 目标构建、PC 模拟器检查和压力测试记录。
5. 交由成员在 390 x 450 真机验收信息密度、GIF 并发、断连/重连和反复退出。

## 14. 上位机与兼容性说明

- MVP **不修改 Agent Pet v1 协议**。只要上位机现有快照携带多个会话，固件即可展示；只发送一个会话时行为自然退化为现有单会话视图。
- 如果某上位机实现尚未聚合多个会话，那是其数据采集覆盖问题，不应通过固件新增敏感字段或私有命令解决；可另立上位机兼容任务。
- `approval_pending` 仍只是只读提示，设备不得回写批准/拒绝。
- 与多 GIF、天气、语音或 OTA 无协议耦合；它们的门禁状态不影响本功能的纯快照展示。
- 若后续合并摸摸 Momo、回忆日历或玩球，必须重新执行触摸和视觉所有权集成测试；本 PRD 不授权隐式改变这些功能的优先级。
