## 3. 问题与目标用户

### 3.1 问题

现在的 Momo 能对“此刻”做出反馈：Agent 工作、木鱼点击、IMU 动作、今日任务花园等；但是第二天之后，用户只能看到累计值或连续天数，无法回答：

- 最近哪几天和 Momo 有过互动？
- 某一天是一起玩、一起完成任务，还是两者都有？
- 陪伴是否形成了温和、可回看的生活痕迹？

当所有反馈都在几秒内消失，宠物更像状态显示器，而不像有共同经历的伙伴。

### 3.2 目标用户

- 日常使用 Agent Pet，希望设备不只是工具状态屏的用户；
- 偶尔完成任务、偶尔与宠物玩耍，不希望被强制打卡或“断签惩罚”的用户；
- 注重本地隐私，不希望互动历史上传云端的用户。

## 4. 产品目标与非目标

### 4.1 目标

1. 保存最近 30 个有效自然日的陪伴类型，形成可回看的 Momo 回忆。
2. 把现有即时互动和 Agent 成果串成长期闭环，不新增另一套养成货币。
3. 让当天回忆实时更新，用户能立刻看见一次有意义互动被 Momo 记住。
4. 本地优先、写入受控、资源固定；异常日期或存储失败不能影响宠物主功能。
5. 不把空白天标成失败，不制造连续打卡压力。

### 4.2 非目标

- 不做云同步、排行榜、社交分享、账号体系或手机端历史页。
- 不新增喂养、饥饿、健康、死亡、惩罚、金币或可购买道具。
- 不保存对话文本、录音、Agent 任务内容、用户输入、位置或个人身份信息。
- 不依赖尚未合入的天气、行为引擎、呼叫 Momo 或摸摸 Momo；这些功能未来可通过受控事件接口扩展，但不作为 MVP 前置条件。
- 不实现完整月历、周计划、提醒事项或 Pomodoro 统计。
- 不新增 GIF、图片、声音、字体、网络请求、线程或高频 timer。

## 5. 核心创意与数据语义

### 5.1 每日回忆类型

MVP 每天只记录三类布尔印记，不记录敏感内容：

| 类型 | 触发证据 | 用户含义 | 去重规则 |
|---|---|---|---|
| 相见 | 当天首次成功进入 Pet 页面且页面完成初始化 | “今天见过 Momo” | 每自然日最多记 1 次 |
| 玩耍 | 用户主动触发一次已经被现有逻辑确认的木鱼/IMU 互动 | “今天一起玩过” | 每自然日最多记 1 次；噪声采样不记 |
| 成果 | Quest Garden 首次确认并领取一个新的 Agent 完成成果 | “今天一起完成过事情” | 复用 generation/任务去重，每自然日最多记 1 次 |

三类印记组成一个 3-bit 日记录。重复点击、反复进入页面或同一 Agent generation 重放不会增加写入或得分。未来功能只能通过公开的受控事件枚举加入，不得让任意 BLE 文本直接写历史。

### 5.2 展示语义

- 最近 30 天按时间从旧到新展示为 30 个“回忆点”；今天有清晰边框。
- 空白：无本地记录或时间未覆盖，不显示失败、哭脸或负面提示。
- 仅相见、包含玩耍、包含成果、三类齐全使用由本项目独立定义的形状/明暗组合；不得依赖单纯红绿含义，需兼顾色弱。
- 点选某天后显示日期与类型摘要，例如“8 月 18 日：见面、玩耍”；不展示任务标题、次数或耗时。
- 当天新增一种印记时，只做一次短暂的本地轻反馈，然后刷新当前点；不得抢占 Agent `NEEDS_INPUT`/`ERROR`、图片接收、播放或系统告警。

## 6. 用户场景与流程

### 6.1 首次使用

1. 用户进入 Pet 页面。
2. 页面初始化完成，今天获得“相见”印记；若 RTC 尚未可信，先只在 RAM 标记并显示“时间同步后保存”。
3. 用户点击独立的“回忆”入口，打开最近 30 天面板。
4. 面板只显示今天的一个回忆点，不弹新手强引导，不要求连续打卡。

### 6.2 当天互动

1. 用户通过现有木鱼触摸或已确认的 IMU 动作和 Momo 玩耍。
2. 现有互动先正常完成，回忆模块接收“玩耍”枚举事件。
3. 如果今天尚无“玩耍”位，内存状态更新并进行一次持久化；已有则不重复写。
4. 用户再次打开回忆面板，可看到今天从“相见”变为“相见 + 玩耍”。

### 6.3 Agent 成果

1. Agent 状态到达 `COMPLETED`，Quest Garden 使用现有去重逻辑生成待领取成果。
2. 用户领取新的成果后，回忆模块记录“成果”。仅状态重放、重复刷新或旧 generation 不记录。
3. 如果 Pet 页面正显示更高优先级状态，只更新数据，不弹回忆反馈。

### 6.4 跨日与回看

1. 日期前进到新的一天时，今天索引滚动，旧记录保持日期标签。
2. 用户打开回忆面板，看到最近 30 个有效自然日；超过窗口的最旧记录自动淘汰。
3. 用户点选某个非空回忆点，查看当天类型摘要。

### 6.5 清除数据

1. 用户在回忆面板进入“清空本地回忆”。
2. 二次确认明确说明只删除回忆日历，不清除 GIF、闹钟或 Quest Garden 累计值。
3. 清除成功后 30 天记录为空；失败则保持原显示并提示稍后重试。

## 7. 功能需求

### 7.1 数据与日期

- 固定保存最多 30 条日记录；每条至少包含可验证日期和 3-bit 类型。
- 数据结构必须有版本和完整性校验或等效的逐字段有效性检查；损坏时安全回空并记录诊断，不崩溃。
- RTC 未同步或日期不合法时，不以 `1970`、全零日期或随机日期落盘。
- 日期前进 1 天：开启新记录；前进多天：中间日期显示为空，不伪造互动。
- 日期回拨：不得覆盖未来记录或重复触发同一日写入；界面提示时间异常，等待可信日期恢复。
- 设备跨月、跨年和闰日必须按公历正确排序；不使用字符串字典序判断日期。
- 事件计数和日期计算必须防止整数溢出、索引越界和 tick 回绕。

### 7.2 持久化与 Flash 磨损

- 只在某日某一类型从 0 变为 1、日期窗口真正滚动、用户清空或版本迁移时写入。
- 相同事件重复到达不得重复写；正常使用每自然日事件写入上限为 3 次，另允许 1 次跨日整理。
- 存储失败时保持 RAM 中的当前会话状态并记录可诊断错误；不得阻断 Pet 页面、BLE、Agent 或音频。
- 写入必须避免“旧数据已删、新数据未写”的不可恢复窗口；实现方案需明确原子性或双版本策略。

### 7.3 UI 与交互

- 回忆入口必须与主宠物点击、长按、连续抚摸、系统返回手势和 Quest Garden 领取控件不冲突。
- 面板创建、更新、销毁以及全部 LVGL API 只在 GUI/LVGL 线程执行。
- 面板关闭或 Pet 页面停止时，全部对象、动画和回调释放；持久层不得保存 LVGL 指针。
- 不新增常驻刷新线程。今天发生事件时事件驱动刷新；日期检查复用现有低频 Pet 刷新/日期路径。
- 高优先级状态到来时，回忆轻反馈可取消；不得改变当前 GIF/图片传输、Agent 状态或音频播放的仲裁结果。
- 提供编译期开关；关闭后不链接回忆模块，不改变现有行为。

### 7.4 隐私与控制

- 数据仅保存在设备本地，协议默认不暴露读写命令。
- 不保存用户内容、任务标题、录音、转写、位置或账号标识。
- 用户可以在设备上查看并清空全部回忆。
- 调试日志只能包含日期、事件枚举和错误码，不输出 Agent 任务文本或其他内容。

## 8. 优先级与状态仲裁

从高到低：

1. 系统安全/关机/告警、图片传输和不可打断的资源更新；
2. Agent `NEEDS_INPUT`、`ERROR`、明确播放/恢复和语音关键状态；
3. 用户主动打开的回忆面板；
4. 回忆新增的短暂轻反馈；
5. 普通空闲宠物动画。

回忆数据记录不依赖 UI 是否可见；UI 反馈被抢占时不补播，不影响数据正确性。

## 9. 资源预算假设

| 资源 | MVP 上限/目标 |
|---|---|
| 持久化有效载荷 | 不超过 512 B，固定容量，不动态扩张 |
| 常驻 RAM 增量 | 不超过 1 KiB（含状态、缓存和校验工作区） |
| Flash 代码增量 | 不超过 10 KiB，不含构建系统对齐波动 |
| 新常驻线程 | 0 |
| 新 timer | 0，优先复用现有日期/状态刷新路径 |
| 回忆面板 LVGL 对象 | 峰值不超过 45 个；关闭后全部释放 |
| 外部素材 | 0 |
| 正常写入 | 每日事件最多 3 次 + 跨日最多 1 次 |
| 刷新性能 | 面板首次完整绘制目标小于 100 ms；无常驻全屏动画 |

实现方案必须用实际 map/size 或构建输出复核增量；若超预算，应先简化对象和文案，不扩大资源上限。

## 10. 验收标准

### 10.1 功能验收

1. 全新数据进入 Pet 页面后，可信日期当天只产生一个“相见”位；反复进出 20 次不增加写入或记录数。
2. 当天第一次有效木鱼/IMU 互动增加“玩耍”；后续 100 次重复互动不重复写入。
3. 新 Agent 成果被 Quest Garden 确认领取后增加“成果”；旧 generation、重复 `COMPLETED` 或重复领取不增加第二次。
4. 三类印记可以任意顺序到达，最终日记录一致；重启后仍一致。
5. 构造连续 35 天数据后只保留最近 30 个自然日，顺序、跨月、跨年和闰日正确，无越界。
6. 日期跳过 3 天时，中间 2 天为空；不会自动补记录或增加连续天数。
7. RTC 无效、回拨和重新同步时不覆盖已有未来记录、不创建伪日期；恢复后可继续记录。
8. 任意单字节/字段损坏、未知版本或截断数据不会崩溃；模块回到安全空状态并留诊断。
9. 清空操作必须二次确认；成功后重启仍为空，失败时旧记录保持。
10. 回忆面板可选择非空日期并展示类型摘要；空白日期不显示负面评价。

### 10.2 集成与稳定性验收

1. 回忆面板打开时收到 Agent `NEEDS_INPUT`/`ERROR`、图片传输或播放状态，按优先级安全让位，数据不丢失。
2. 反复打开/关闭 Pet 与回忆面板各 200 次，LVGL 对象数量回到基线，无定时器回调访问已删除对象。
3. 功能编译关闭时，现有 Pet 交互、Quest Garden、BLE、音频和 GIF 行为与基线一致。
4. 主机单元测试覆盖日期滚动、回拨、闰年、容量、事件幂等、损坏恢复、清空和整数边界。
5. 按仓库真实说明完成目标板全量编译；新增源文件以 `-Wall -Wextra -Werror` 或项目等效严格告警通过。
6. 检查数组索引、指针 NULL、整数转换、持久化错误传播、LVGL 线程边界和页面销毁顺序。

### 10.3 硬件验收

- 真实触摸回忆入口与宠物点击/返回手势不冲突；
- 木鱼与 IMU 仅在现有互动判定成功后记忆，不被传感噪声刷写；
- 断电重启、RTC 未同步后同步、手工调整时间、跨日待机后历史正确；
- 连续运行 24 小时无明显卡顿、异常 Flash 写入或宠物状态抢占；
- 硬件未执行前必须标注“待硬件验收”，不得以模拟器或主机测试代替。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 与 Quest Garden 连续天数看起来重复 | 用户不理解新价值 | 日历只讲“共同回忆类型”，不显示另一套 streak、币或等级 |
| RTC 无效/回拨 | 日期错乱、覆盖历史 | 日期有效性门禁、单调水位、回拨只读保护、恢复测试 |
| 高频互动磨损 Flash | 寿命下降 | 位从 0 到 1 才写；每日每类一次；重复事件幂等 |
| 存储中断或损坏 | 历史丢失、启动异常 | 版本/校验、原子写策略、损坏回空且不影响主功能 |
| 入口与抚摸/长按/返回冲突 | 误操作 | 独立命中区域；事件冒泡与优先级测试；不复用宠物主体长按 |
| LVGL 对象泄漏 | 多次打开后崩溃 | 页面级所有权、统一销毁、200 次生命周期测试 |
| 事件来源重复或伪造 | 记忆失真 | 只接受内部枚举；成果复用 generation 去重；BLE 文本不得直写 |
| 空白天带来打卡焦虑 | 降低陪伴感 | 空白保持中性，不清零奖励、不出现惩罚/死亡/责备 |
| 来源无许可证 | 法务风险 | 彻底独立实现，不复制任何表达或代码；提交记录保留隔离说明 |

## 12. 实现阶段门禁与回退

- 嵌入式实现方案必须先定义纯 C 日期/环形记录模块与 GUI 适配层边界，再写代码。
- 方案必须明确持久化原子性、版本迁移、日期回拨策略、事件幂等、LVGL 生命周期、资源测量和测试矩阵。
- 功能通过独立 Kconfig/编译开关关闭后，Pet 页面恢复原有行为；数据保留但不读取/展示。
- 发生存储错误、RTC 异常或 UI 分配失败时，只禁用回忆面板或退化为 RAM 状态，不影响 Agent、BLE、GIF、音频和 Quest Garden。
- 开发完成标志必须同时包含：本 PRD 提交、实现方案提交、代码/测试提交、实际构建命令与结果、资源增量和待硬件验收项。

## 13. 产品优先级说明

- 用户价值：从即时反馈提升到长期共同经历，增加宠物感而不是工具感。
- 差异化：填补现有“只有今日/累计、没有逐日回看”的空白。
- 可行性：全部输入和基础设施已存在，设备端能独立闭环。
- 风险：固定资源、低频写入、无外部资产、可编译关闭，风险可控。
- 因此列为 P1；一次只推进这一项，不同时开发罗盘、天气素材、闹钟或语音等候选。
