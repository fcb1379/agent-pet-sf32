## 4. 与目标项目现状对照

对 `origin/master` 的 `app_pet.c`、Agent Pet 协议、任务花园文档和已有交互进行对照后，现状包括：

- Momo 待机/状态展示，以及 `IDLE`、`RUNNING`、`NEEDS_INPUT`、`COMPLETED`、`ERROR` 等 Agent 状态。
- JPEG/GIF 接收、多个槽位选择、GIF 播放和打字/表情事件。
- 木鱼点击、任务花园、状态提示、图片传输进度和 IMU 入口。
- 页面已有多个 LVGL timer，并在页面退出时进行生命周期清理。

### 4.1 与已有方向的差异

| 已有能力/方向 | 主要因果关系 | 与玩球的边界 |
| --- | --- | --- |
| 多 GIF | 上位机下发表情资源，设备选择/播放 | 属于资源与表现层；玩球是本地空间交互和状态机，不要求新增 GIF |
| 多状态自主行为 | 无输入时按规则切换状态/表情 | 属于自主调度；玩球由用户拖放球触发，输入、运动和碰撞可观察 |
| 摸摸 Momo | 在宠物区域连续触摸，获得安抚反馈 | 属于直接身体接触；玩球的触点落在独立球对象，形成投掷和追逐 |
| Agent 任务花园 | Agent 完成任务后积累、领取成果 | 属于跨任务积累；玩球不读取 Agent 任务、不累计、不持久化 |
| 木鱼 | 单点点击触发计数/声音 | 属于离散点击；玩球需要拖拽轨迹、释放速度、边界运动和接触闭环 |

### 4.2 排除的扩张

- 不把球做成上位机下发的新素材或新 GIF 槽。
- 不加入金币、商店、道具耐久、饥饿、经验或成长等级。
- 不新增 BLE 命令，不让设备反向控制 Agent。
- 不保存球的位置、次数、胜率或每日连续记录。
- 不在首版加入音频素材、振动或 IMU 投掷；这些必须在 MVP 真机稳定后另立需求。

## 6. 推荐落地范围

本次只推荐一个创意进入开发：

1. 页面进入后，在安全区域显示由 LVGL 基础样式绘制的圆球。
2. 用户按住球并拖动；球跟随触点但始终被限制在内容区域内。
3. 用户松手时，依据有限的触点位移产生有上限的二维速度。
4. 球按固定周期做整数/定点运动，并在内容边缘衰减反弹。
5. Momo 以有上限的速度向球靠近；发生接触时显示短反馈。
6. 速度衰减停止、成功接触或达到超时后，结束本轮并平滑回到空闲状态。
7. Agent 紧急状态、图片传输、外部表情播放或页面退出优先中止玩球，且不得遗留 timer 或对象引用。

## 7. 资源与质量门槛

- 纯业务状态小于 256 B，不使用动态业务内存。
- 新增基础 LVGL 对象不超过 5 个。
- 最多新增一个 40–50 ms timer；禁止新建 RT-Thread 线程。
- 目标新增 Flash 小于 8 KiB，以同一工具链的开关前后结果为准。
- 零外部图片、GIF、字体和音频素材。
- 不新增 BLE/USB 协议、FlashDB/share_prefs 记录或上位机改动。
- 目标刷新体验不低于 20 FPS；真机不得出现明显残影、卡顿或触点跳变。
- 真实硬件验收必须覆盖拖拽坐标、屏幕边缘返回手势冲突、动画中退出、重复开始/结束和页面反复进入/退出。

## 8. 决策

- **可行性：可行，建议进入受控 MVP 开发。**
- **优先级：P1。** 原因是能直接提升陪伴感，且不依赖上位机、网络、素材和新硬件。
- **继续门槛：** 技术方案必须先证明状态机固定内存、LVGL 单线程边界、页面退出清理、Agent/表情优先级和真机回退路径；任一关键条件不成立时，保留 PRD 和纯状态机验证，不强行接入 UI。
