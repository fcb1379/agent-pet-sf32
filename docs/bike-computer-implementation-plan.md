# SF32 GPS 码表实施计划

日期：2026-09-17

分支：`codex/feature-bike-computer`

基线：`d2192dc Add persistent watch settings`

## 1. 开发原则

- 保留 SiFli-SDK、RT-Thread、LVGL v8 和当前 GUI app framework。
- 先完成模组电气接口确认和文档评审，再修改代码；转接板网络与实物电气测量分别留存证据。
- 每一阶段单独提交、单独构建并记录资源变化。
- 不修改 SDK 源码；板级差异放在项目内 board overlay。
- 每次提交完成后立即推送到远端同名分支，并核对本地与远端提交哈希一致；烧录、创建 PR 和合并仍需用户明确要求。

## 3. 阶段与门禁

### 阶段 0：硬件接口确认

输出：

- GPS 转接板引脚表。
- 模组上电/复位/串口时序。
- 黄山派引脚复用和冲突检查。
- 电流预算和天线注意事项。

当前结论：DX-GP10-A 载板接口及用户转接板网络已确认；UART1 与调试口冲突，排除使用；GNSS 使用 UART3，SF32 PA35/TX 接载板 RXD，载板 TXD 接 SF32 PA36/RX。转接板还引出 `GPS_PPS`、`GPS_WAKE`，供电网络为 `GPS_5V`/`5V_RAW`。PA35/PA36 与 USB DP/DM 复用，当前配置保持 USB Device/Host 关闭；实物电压、电平、连接方向和天线仍是设备验收门禁。

门禁：无硬件依赖的数据模型测试通过；没有动态内存。

门禁：台架连续 30 分钟稳定；断开/重连、丢星和脏数据可恢复。

### 阶段 3：390 x 450 码表 UI

当前进度：主数据、定位详情、骑行总结三页和阶段 6 的离线地图页已完成；主数据页提供开始/暂停与保存结束，总结页提供保存/丢弃，KEY2 可完成开始/暂停/继续和保存结束。`bikedemo on/off/status` 可在无 GPS 模组时每秒生成固定容量模拟定位，UART3 缺失时工作线程仍可启动，界面明确显示 `DEMO`。

#### X-TRACK 比例布局复刻

- 以 X-TRACK `DialplateView` 的 240 x 240 画布为归一化参考，横向尺寸按 `390 / 240`、纵向尺寸按 `450 / 240` 独立换算，不直接复用上游绝对像素。
- 主数据页保持上游三段式占比：速度区 `y=-36/240`、`h=142/240`；四项骑行数据区 `y=106/240`、`h=90/240`；三个操作区从 `y=196/240` 开始、`h=40/240`。
- 四项骑行数据按上游顺序显示平均速度、移动时间、单次里程和卡路里，采用 2 x 2 等比例布局；海拔和诊断信息保留在定位详情页，避免骑行主屏信息过载。
- 底部三个操作区按屏幕宽度 `1/6`、`1/2`、`5/6` 设置中心位置，分别进入地图、短按开始/暂停/继续且长按结束、进入状态详情。
- 字体按信息优先级选择 SF32 已注册字号，保证速度显著大于指标值和单位；不复制上游字体像素尺寸，也不恢复曾导致实机文字异常的 Montserrat 编译字体。
- 地图页保留全屏瓦片，并按 X-TRACK `LiveMapView` 的比例在左下角叠加速度、里程和时间，在右侧保留缩放状态与触控区。

任务：

- 支持触摸和按键；模拟数据模式可在无 GPS 时演示。
- UI 刷新频率与 GNSS 更新解耦，避免每帧重建对象。

门禁：PC/设备布局检查通过；连续运行无明显堆增长和卡顿。

### 阶段 6：X-TRACK 离线地图与实时轨迹

当前进度：已按 X-TRACK 的 Web Mercator 和 `/MAP/<zoom>/<x>/<y>.bin` 组织方式重写固定容量地图层，补齐上游 `mapWGS84` 对应的 WGS-84/GCJ-02 坐标切换、`mapDirPath` 多地图源选择、`mapExtName` 文件扩展名选择和 `arrowTheme` 的 `default/light/dark` 定位箭头主题并持久化，完成主机转换/投影/路径边界/主题解析测试和 SF32 目标构建。地图目录使用当前介质内的安全逻辑绝对路径，TF 卡挂载时自动解析到 `/sd`，拒绝路径穿越、空段和截断；扩展名限制为 1~7 位字母数字并只改变文件名，内容仍使用 LVGL v8 RGB565 二进制格式。LVGL 第四页已支持 3 x 3 瓦片、当前位置方向箭头和 128 点静态实时轨迹；箭头使用 40 bytes 只读 1-bit Alpha 蒙版，按 GNSS course 以 0.1 度旋转，定位无效时隐藏，主题切换即时重着色而不分配运行期像素缓冲。启动或切换地图源时扫描当前地图介质的 0~19 级纯数字目录并以实际最小/最大目录限制缩放，未检出合法目录时安全回退到 0~19 级，当前缩放会钳位到可用范围。轨迹按上游方式固定存于 16 级全局像素坐标，缩放时重投影而不清空，缓存由完整投影点缩减为每点 8 bytes。针对 SDK 文件图片解码器不支持 SPI-MSD/FAT 打开的限制，已增加严格校验 LVGL v8 头部和精确长度的固定 PSRAM 瓦片加载器；瓦片缺失或损坏时保留定位/轨迹显示。实际页面视觉效果留到其他实机验证环境。

地图平移性能已改为九槽增量缓存：每个固定 PSRAM 槽记录缩放级别和瓦片坐标，跨过单条瓦片边界时保留仍在视口中的六张瓦片，只读取新进入的三张；缺失文件的结果也会缓存，避免定时刷新重复访问。TF 卡启动探测失败时，进入码表应用会重新初始化 SPI-MSD 并尝试挂载 `/sd`，后插卡可通过重新进入应用触发识别。以上已完成主机核心回归和 SF32 目标构建，真实 16 GB 卡的挂载与滑动流畅度仍需实机确认。

任务：

- 保持 GNSS/GPX 为 WGS-84，地图层按持久化设置选择 WGS-84 或 GCJ-02，再执行固定容量 Web Mercator 投影和瓦片路径生成。
- 扫描 `/MAP` 或 `/sd/MAP` 下的合法缩放目录，按介质实际最小/最大级别约束缩放，目录为空或不可访问时保持安全回退范围。
- 在 LVGL 页面中显示离线瓦片、当前位置、缩放控件和实时轨迹，缩放后保留当前轨迹。
- 地图文件缺失或损坏时安全降级，不影响码表主数据和 GPX 记录。
- 使用 `bikeset arrow <default|light|dark>` 持久化 X-TRACK 定位箭头主题，运行期按 GNSS 航向旋转，定位失效时隐藏。

门禁：投影/路径主机测试与目标构建已通过；瓦片格式、缩放、轨迹叠加和缺图降级需实机验收。

### 阶段 7：存储与扩展功能

范围状态：X-TRACK 原工程使用 Micro SD 存放地图和轨迹，并在 SystemInfos 数据链中读取计步与磁力计信息；当前 SF32 工程已按黄山派基板 pinmux 启用 SPI1 TF 与 SDK SPI-MSD，在 `/sd` 独立挂载已有 FAT 文件系统，并为轨迹/地图提供 TF 优先、板载 Elm FAT 回退。黄山派官方资料确认板载 LSM6DS3TR-C 与 MMC5603NJ，当前 QADSPI 构建下已通过 I2C2 PA39/PA40 接入计步和电子罗盘。

任务：

- TF 挂载成功时使用 `/sd/MAP` 和 `/sd/tracks`，无卡或挂载失败时回退 `/MAP` 和 `/tracks`；禁止启动时自动格式化用户介质。
- 计步初始化先读取 WHO_AM_I，驱动开启后回读 ODR/功能引擎/计步使能位；固定栈线程发布步数、状态和错误计数，统计页不得直接访问 I2C。
- 磁力计初始化先读取产品 ID，采用单次测量、自动 SET/RESET、数据就绪超时和完整 9 字节读取；固定栈线程发布三轴磁场、运行时校准进度、航向和错误计数。
- FIT 输出和路线导航不是 X-TRACK 主线必备功能，保留为后续独立扩展。

当前进度：TF 路径回退、当前介质总/剩余容量快照及系统信息页显示、板载计步和 MMC5603NJ 电子罗盘均已完成源码、主机回归和目标构建。容量只在启动和轨迹结束/丢弃后从文件系统线程路径更新，LVGL 只读互斥保护的缓存；当前 SDK SPI-MSD 是启动一次性探测，且板级未定义卡检测 GPIO，因此不声明运行期热插拔。计步累计纯逻辑覆盖复位、16 位回绕、异常跳变和 32 位饱和；罗盘纯逻辑覆盖水平面硬铁中心校准、进度、四象限航向和边界参数。生成配置仅启用 LSM6DSL step，未注册不需要的加速度/陀螺仪设备；磁力计使用项目内定长驱动，规避 SDK MMC56x3 封装的缓冲越界与 I2C 断言路径。

门禁：TF、计步和电子罗盘的源码/构建证据已具备；真实卡兼容性、异常拔卡和断电测试，以及 WHO_AM_I/产品 ID、计步准确率、罗盘安装轴向与标定、功耗和 PA39/PA40 实际信号，放在所有代码检查之后。

### 阶段 8：电源状态与代码完成性审计

当前进度：黄山派 GPADC1 内部 VBAT channel 7、片上 `charge` 状态、电压低通、百分比回差和 UI 诊断已完成源码、主机回归与目标构建。电量百分比沿用 X-TRACK 的 3.3~4.1 V 线性估算，只作为电压估算值，不宣称为库仑计 SOC。X-TRACK 的 `soundEnable`、`MusicPlayer` 事件序列已适配到黄山派片上 Audio Codec/扬声器：固定静态线程和消息队列按 16 kHz/16-bit/单声道生成方波 PCM，支持启动、错误、连接、断开、信号不稳、充电开始/结束和无操作提示，GNSS、骑行控制和充电状态只做非阻塞投递。`bikeset sound <0|1>` 持久化开关，`bikesound play <event>` 可供后续实机逐音验证。

代码完成性审计已按 X-TRACK 上游源码与 README 主线功能逐项核对：速度、距离、时间、按持久化骑手体重估算卡路里、航向、离线地图、WGS-84/GCJ-02 坐标选择、地图目录/扩展名/箭头主题选择、实时位置/轨迹、计步、经纬度/海拔、GPS 校时、GPX 导出和掉电累计保存均已有对应实现。可主机编译模块通过 `-Wall -Wextra -Werror`、ASan/UBSan 和 GCC `-fanalyzer`，SF32 HCPU 目标完成链接与镜像生成。X-TRACK 的 `language` 字段只在 `DP_SysConfig` 注册存储，源码中没有任何读取消费者或本地化资源切换，因此不移植一个无效的语言开关；X-TRACK 没有环境光自动亮度功能，黄山派当前板级与 SDK 也未发现环境光器件定义，因此不把自动亮度列为漏移植项。

门禁：代码移植和代码侧检查完成；电池曲线、充电状态、低电压行为、提示音响度/音色/混音占用、整机功耗以及前述各外设的真实设备行为统一在其他实机验证环境处理，验证中发现的问题再直接回到对应驱动或业务模块修正。
