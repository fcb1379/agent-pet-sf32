# PRD：呼叫 Momo / 寻宠回声

## 1. 文档信息

- 日期：2026-08-11。
- 优先级：P1。
- 目标版本：固件与 Android 伴侣端到端 MVP。
- 目标基线：`fcb1379/agent-pet-sf32` 的 `origin/master@75bcc5720a00c46efa924ba41b5b8c5c53a52622`。
- 来源证据：`TurtleWhal/GWatch-Paris@39beeb04ffde8c8507a1bc02fd45152e9003be15`，提交时间 `2026-08-10T04:04:43Z`，公开提交展示了手机发起找手表、设备唤醒、提示、停止和超时的可穿戴场景。
- 知识产权边界：来源仓库无明确许可证，其 Gadgetbridge 生态还可能涉及 AGPL。本文只引用需求事实；实现不得复制来源或 Gadgetbridge 的代码、协议、JSON 字段、UI、文字、参数、图标、声音和素材。

## 2. 问题与目标用户

### 2.1 问题

用户将手表/电子宠物放在桌面、沙发或包内后，虽然手机仍与设备保持 BLE 连接，却没有办法让设备主动显形和发声。现有 Android 伴侣能设置闹钟、同步时间和传图片，但缺少“现在就回应我”的即时入口。

普通“找手表”只有工具感。Agent Pet 更适合把它包装成一次轻互动：用户从手机呼叫 Momo，Momo 醒来回答“我在这里”，用户在设备上点它或在手机上停止，形成明确完成反馈。

### 2.2 目标用户

- 在室内短距离内临时找不到设备、但 Android 伴侣仍显示已连接的用户。
- 希望确认设备在线、屏幕和扬声器仍可工作的研发/测试成员。
- 喜欢宠物具备“回应主人”感受，但不希望增加养成惩罚或强制打卡的用户。

## 3. 产品目标与成功指标

### 3.1 目标

1. 在 Android 伴侣提供真实可点击的“呼叫 Momo”入口。
2. 从点击到设备进入可感知状态的目标延迟不超过 1 秒；设备必须先回协议结果，再由异步事件报告结束原因。
3. 设备从任何正常页面都能显示找寻覆盖层，且停止后恢复原页面、原 GIF 和 Agent 状态。
4. 呼叫最长 60 秒自动停止，不因重复包、手机切后台或 BLE 断开而无限响铃。
5. 不增加素材、不占 GIF 槽、不写 Flash、不依赖云端、定位、账号或 Gadgetbridge。

### 3.2 成功指标

- 20 次正常呼叫中，Android 点击到设备视觉响应 P95 ≤ 1 秒。
- 20 次设备点击停止与 20 次手机停止均 100% 在 1 秒内停止声音/动画，并给出本地或远端可见的结束状态。
- 重复、乱序、断连、超时、闹钟抢占测试中无无限响铃、无状态损坏、无页面悬挂。
- 连续呼叫 50 次后，LVGL 对象数、任务数和可用堆不出现持续下降。

## 4. 核心场景与流程

### 4.1 正常呼叫与设备端停止

1. Android 伴侣已连接并完成 `HWS1` 能力协商。
2. “呼叫 Momo”按钮可用；用户点击。
3. 伴侣发送带请求 ID 的 START，按钮切换为“停止呼叫”，并显示“正在呼叫”。
4. 固件校验当前未处于闹钟/计时器响铃、未进行图片/GIF 传输后，返回已接受；重复 START 不延长超时。
5. 设备唤醒，从当前页面进入全屏或顶层的 Momo 找寻覆盖层；保留底层页面和宠物状态。覆盖层显示当前可用宠物形象、“我在这里”和停止提示，不新建 GIF 资源。
6. 当前本地音量大于 0 且无静音/勿扰策略阻止时，按安全音量播放间歇提示；否则仅视觉提示。
7. 用户点击宠物或停止按钮；设备立即停止提示、清理覆盖层并恢复进入前页面。
8. 固件向仍连接的伴侣发送结束原因 `USER_STOP`；伴侣恢复“呼叫 Momo”按钮并显示“已找到”。

### 4.2 手机端停止

1. 呼叫进行中，用户在 Android 伴侣点击“停止呼叫”。
2. 伴侣发送 STOP；固件无论是否仍处于 ACTIVE 都返回幂等结果。
3. 若正在呼叫，设备停止并恢复页面；若已经停止，不能再次播放或报错。
4. 伴侣显示 `PHONE_STOP` 或“已停止”。

### 4.3 超时与断连

- START 被接受后，以设备单调时钟计 60 秒，达到上限自动停止，原因 `TIMEOUT`。
- 呼叫中手机进入后台不影响设备的 60 秒本地闭环；Android 不要求常驻后台服务。
- 呼叫中 BLE 断开：设备继续视觉/声音提示，直到用户本地停止或 60 秒超时，保证“已发出的寻找”仍有价值；因为链路已断，结束事件允许丢失。
- 重连后伴侣查询状态；若仍 ACTIVE，显示剩余时间和停止按钮；若已结束，显示空闲，不补发旧事件。
- START 尚未被设备接受就断连：伴侣显示失败，设备不得进入呼叫状态。

### 4.4 设备不在 Pet 页

- 无论当前是时钟、音乐、文件或普通应用页，呼叫都应使用系统级顶层覆盖层或安全导航进入找寻页。
- 必须记录进入前的有效页面引用/应用 ID；停止后仅在对象仍有效时恢复，否则回到稳定的 Pet/主页面。
- 呼叫不得销毁当前页面、远端 GIF 解码器或 Agent 快照；不能用“重启应用”冒充恢复。

## 5. 功能需求

### 5.1 Android 伴侣

- 连接并协商到新能力后显示“呼叫 Momo”按钮；未连接、能力不支持或图片传输中必须禁用。
- 点击后立即防抖，等待明确响应；不能因多次点击并发发送多个 START。
- ACTIVE 时按钮变为 STOP，并显示已用/剩余时间或至少显示进行中。
- 处理 `ACCEPTED`、`ALREADY_ACTIVE`、`BUSY_ALARM`、`BUSY_TRANSFER`、`UNSUPPORTED`、`TIMEOUT` 和断连错误。
- 应用切后台不启动新的常驻服务；回前台/重连后通过状态查询恢复 UI。
- MVP 至少完成 Android 原生端；Web PWA 与 iOS 入口不作为本次完成门槛，但协议不得阻碍后续接入。

### 5.2 固件状态机

- 状态至少包含 IDLE、ACTIVE、STOPPING；所有转换集中管理，BLE 回调不得直接操作 LVGL、播放音频或阻塞。
- 请求 ID/序列必须支持重复检测；同一 START 重传只返回原状态，不重置 60 秒期限、不重复创建 UI/定时器、不重复开始声音。
- ACTIVE 期间收到新的 START 返回 `ALREADY_ACTIVE`，不得延长超时；STOP 在任意状态幂等。
- 所有结束路径汇聚到同一清理函数，保证音频、覆盖层、唤醒锁、计时器和状态一次性释放。
- 超时使用单调 tick 并正确处理回绕；不得依赖可被手机校时回拨的 RTC。

### 5.3 显示与宠物交互

- 使用当前已选中的 Pet GIF 或内置宠物形象，不新增/复制任何外部素材，不占用和改写 5 个用户 GIF 槽。
- 覆盖层只增加短文本、轻量呼吸边框/色块和停止热区；不改变自主行为状态、天气状态、功德、任务花园、Agent 快照或远端 `PLAY/RESTORE` 所有权。
- 点击宠物和明确停止按钮都可停止；触摸事件只消费在覆盖层内，停止后必须恢复原触摸行为。
- 若 Pet 页当前未创建，允许使用现有默认宠物资源创建最小找寻覆盖层；停止后完整释放临时对象。

### 5.4 声音、音量、静音与勿扰

- 使用目标仓库已有本地提示音/闹铃能力，不新增音频素材。
- 音量遵守 `watch_settings_get_local_volume()`；音量为 0 时只显示、不临时改音量。
- 当前主分支没有全局勿扰模型；MVP 不新增整套勿扰设置，但音频策略必须提供“允许发声”判断入口。未来有勿扰状态时默认只视觉提示，不可绕过用户设置。
- 提示采用间歇节奏，最长 60 秒；不得在 BLE 回调或 LVGL 回调中长时间阻塞。
- 不得永久改变本地音乐或蓝牙音乐音量。若无法安全暂停并仅恢复由本功能暂停的音乐，则保留视觉提示、跳过找寻声音，不能强抢音频资源。

### 5.5 闹钟、计时器与音乐并发

- 优先级：正在响铃的每日闹钟/计时器 > 呼叫 Momo > 普通音乐提示。
- START 到达时闹钟或计时器已经响铃：返回 `BUSY_ALARM`，不创建覆盖层、不改变响铃状态。
- 呼叫进行中闹钟/计时器开始：立即以 `PREEMPTED_ALARM` 结束呼叫并释放其资源，再让正式响铃接管；不得吞掉闹钟。
- 图片/GIF 传输处于接收、校验或切换阶段时返回 `BUSY_TRANSFER`，避免 BLE 带宽与 GIF 双缓冲竞争。
- 普通本地/蓝牙音乐播放时不得破坏播放队列。实现方案必须选择经验证的短提示音混音/暂挂恢复方式；无法证明安全时降级为纯视觉。

### 5.6 Agent、GIF 与其他状态优先级

- 找寻覆盖层是系统级临时层，不是新的宠物行为状态。
- `NEEDS_INPUT`、`ERROR`、打字、远端 `PLAY`、任务花园、天气和自主行为的数据必须继续保留；覆盖层消失后按原优先级重新渲染。
- 找寻期间不允许主动切换 GIF 槽或发送 `RESTORE`，避免夺取上位机/行为引擎的表情所有权。
- 图片传输硬阻塞；正式闹钟/计时器硬抢占；其他 Pet 状态只在视觉上被顶层覆盖，不被重置。

### 5.7 协议语义

- 复用目标已有 `HWS1` 控制特征与请求 ID，不新增 GATT 服务/UUID，不采用来源/Gadgetbridge 的 JSON 协议。
- 能力协商增加独立能力位/字符串，使旧固件上的按钮保持隐藏或禁用。
- 至少支持 START、STOP、STATUS；响应区分接受、幂等、忙、参数错误和不支持。
- 设备异步结束事件包含原因：`USER_STOP`、`PHONE_STOP`、`TIMEOUT`、`PREEMPTED_ALARM`；事件不携带个人信息。
- 帧长度、数字解析和字符串拼接必须有边界；未知操作不改变当前状态。

## 6. 范围与非范围

### 6.1 本次范围

- `HWS1` 能力、START/STOP/STATUS 和结束事件。
- 固件状态机、60 秒单调超时、系统级 Momo 覆盖层、设备端停止。
- 复用现有声音的安全策略、音量 0 降级、闹钟/计时器和传输抢占。

### 6.2 非范围

- 新增全局勿扰中心、手机后台常驻服务、推送通知。
- iOS/Web 入口和 Gadgetbridge 插件。
- 新 GIF、图片、字体、铃声、振动马达驱动或外部素材。
- 多设备同时寻找、账户体系、寻找历史和奖惩/养成数值。

## 7. 验收标准

1. Android 已连接且固件声明能力时按钮可用；旧固件、未连接和传输中不可发起。
2. Android 点击 START 后设备 ≤ 1 秒出现 Momo 找寻视觉反馈；音量大于 0 且音频空闲时有间歇声音。
3. 音量为 0 时全程不发声、不改音量，视觉与停止仍正常。
4. 设备从 Pet、时钟、音乐三个页面分别被呼叫，设备端停止后恢复原页面；原 GIF/Agent 状态一致。
5. 手机 STOP、设备点击、60 秒超时分别得到正确结束状态；重复 STOP 不报错、不重播。
6. 同一 START 连续重发 100 次只创建一个会话、一个 UI 层和一个超时源，期限不延长。
7. START 未接受前断连不启动；ACTIVE 后断连继续到本地停止/超时，重连 STATUS 能恢复当前状态。
8. 闹钟/计时器已响时 START 返回 BUSY；呼叫中触发闹钟，找寻在正式响铃前被清理且结束原因为抢占。
9. GIF/图片传输中 START 返回 BUSY，传输结果、槽位摘要和持久文件不受影响。
10. `NEEDS_INPUT`、`ERROR`、远端 PLAY、打字、任务花园、天气/自主行为分别在找寻前后保持数据与显示所有权。
11. 连续 50 次 START/STOP 后无 LVGL 无效对象访问、内存持续下降、任务/定时器泄漏、音频卡死或 BLE 回调阻塞。
12. Android 测试、协议主机测试、PC 模拟器和真实目标构建全部记录实际命令、退出码和警告；真机声音、屏幕唤醒、页面恢复、断连和功耗标为待硬件验收，不能用模拟器冒充。

## 8. 资源预算假设

- 新增图片/GIF/字体/音频素材：0 B。
- 固件代码与只读数据：目标净增 ≤ 20 KiB Flash。
- 固件静态 RAM：目标净增 ≤ 1 KiB；不得增加常驻大缓冲。
- 临时 LVGL 堆：ACTIVE 期间目标峰值 ≤ 8 KiB，停止后回到基线波动范围。
- 新增 RT-Thread 常驻线程：0；优先复用现有工作线程/事件和 LVGL 上下文。
- 新增长驻定时器：0；允许会话期间存在 1 个有界超时源，停止后释放。
- BLE：单次 START/STOP/STATUS 为短控制消息，不新增服务，不与图片/GIF 批量传输并发。
- 功耗：单次会话最长 60 秒；真机需量化亮屏与音频电流，不能仅凭静态预算宣称达标。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 无许可证来源或 Gadgetbridge AGPL 污染 | 代码/协议无法合规复用 | 只保留需求事实；基于现有 HWS1 独立设计，评审 diff 不得出现来源代码、字段、素材或依赖 |
| Android 有入口但固件只做测试桩 | 用户仍不可用 | 完成门槛强制要求 Android 真按钮、协议、固件 UI/声音、停止回执同一分支交付 |
| 呼叫抢占正式闹钟/计时器 | 关键提醒丢失 | 正式响铃硬优先；开始时 BUSY，过程中 PREEMPT 并先清理找寻 |
| 音乐恢复错误或音量被改变 | 用户体验和音频状态损坏 | 仅恢复由本会话拥有的状态；不能证明安全则纯视觉；绝不永久修改音量 |
| BLE 重复/乱序导致无限响铃 | 打扰与耗电 | 请求幂等、期限不可被重复包延长、60 秒单调超时、统一清理 |
| 手机切后台/断连收不到结束事件 | 伴侣 UI 与设备不一致 | 设备独立闭环；回前台/重连后 STATUS 对账，不补发过期事件 |
| 非 Pet 页覆盖后无法恢复 | 页面泄漏或黑屏 | 使用系统层/有效对象校验，保存应用 ID，失败时回稳定页；模拟器覆盖多页面 |
| 最新主分支素材已明显增大 | Flash 余量风险 | 零新增素材、构建后提供 map/size 差值，超预算则不完成 |
| 未配对 BLE 可触发骚扰 | 近距离重复提示 | 仅允许当前控制连接、速率限制、60 秒上限；不传敏感数据；后续随全局配对策略增强 |

## 10. 可行性结论

**可行，建议 P1 落地。**

目标仓库已经同时具备 Android 真实伴侣、`HWS1` 控制面、设备异步通知、Pet UI、屏幕应用框架、本地音量和闹钟/计时器音频服务。相比新增天气服务或通知权限，本功能不依赖云端和敏感数据，能够在单次任务内形成真实入口到设备反馈的闭环。

最大技术风险不是协议，而是音频与正式闹钟抢占、跨页面 LVGL 生命周期和最新主分支的资源余量。嵌入式方案必须先提交，明确这些约束与降级路径，再实施。若无法安全发声，允许以纯视觉完成部分场景，但“Android 真实入口、设备视觉回应、双端停止/超时和明确回执”缺一不可。

## 11. 真机验收建议

1. 将开发分支固件烧录到 SF32LB525，安装同分支 Android debug APK。
2. 在 Pet、时钟、音乐页分别呼叫，测点击到视觉/声音延迟并停止，确认返回原页面。
3. 将本地音量设为 0 和非 0 分别测试；确认 0 音量未被自动抬高。
4. 呼叫中关闭 Android 屏幕、切后台、关闭蓝牙，分别验证设备本地停止和 60 秒超时。
5. 呼叫前/中触发闹钟与计时器，确认正式响铃不丢失；同时测试普通音乐播放。
6. 图片/GIF 传输期间尝试呼叫，确认明确 BUSY 且传输最终摘要一致。
7. 连续 50 次呼叫/停止，采集串口日志、堆余量、LVGL 对象/定时器和音频状态。
8. 测量待机与 60 秒视觉+声音呼叫的平均/峰值电流，记录屏幕唤醒后的恢复情况。
