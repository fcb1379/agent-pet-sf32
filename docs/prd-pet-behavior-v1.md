# Agent Pet 多状态自主行为 PRD v1

## 背景与问题

当前宠物页面能够展示 Agent 任务状态、单套自定义 GIF、敲木鱼互动和任务花园，
但宠物本身没有连续的情绪和行为。用户触摸、晃动设备或长时间未互动后，宠物的
反馈仍然基本相同，难以形成陪伴感。

## 产品目标

- 让宠物根据时间、用户触摸、IMU 动作和 Agent 任务状态自主切换表现。
- 用可解释、可复现的规则状态机建立“事件 -> 情绪 -> 反馈 -> 长期关系”闭环。
- 在没有新增 GIF 素材时仍能通过动作、颜色和文字完整工作。
- 支持后续按状态放置独立 GIF，且任一时刻只解码一套素材。

## 目标用户

- 希望设备具有陪伴感而不只是状态看板的用户。
- 会通过点击、长按、抬腕或晃动主动与宠物互动的用户。

## V1 范围

### 与上位机多 GIF 同步的协同规则

- 主分支提供的 0~4 号 GIF 槽位继续由上位机管理；槽位编号不绑定 Happy、Sleepy 等
  自主情绪语义，避免上位机素材被本地算法误用。
- 上位机 `PLAY(slot)` 是临时视觉覆盖，优先于自主状态 GIF；`RESTORE`、蓝牙断开后
  立即把视觉控制权交还当前自主状态，覆盖期间不修改 affinity、energy、arousal。
- 上位机打字动画运行期间暂停自主 GIF 替换；停止打字后恢复当前自主状态。
- 远端槽位缺失或损坏时回退到 0 号基础槽位或内置 mascot，不回退到语义不确定的
  其他槽位。
- V1 的 11 个自主状态素材仍使用 `/pet/<state>.gif`。若后续希望全部通过上位机同步，
  需要新增“状态角色到槽位”的版本化清单或扩展专用槽位，不能仅依赖现有 5 个匿名槽位。

### 基础情绪

- Calm：默认平静。
- Happy：近期获得正向互动。
- Curious：检测到轻度动作或随机探索。
- Sleepy：夜间或较长时间没有互动。
- Lonely：超过一天没有互动。

### 短时反应

- Celebrate：三连击或 Agent 任务完成。
- Startled：强烈撞击。
- Annoyed：短时间内连续点击过多。

### Agent 覆盖状态

- Working、Needs input、Error 继续使用现有任务状态作为最高优先级显示。
- Agent 覆盖结束后恢复此前宠物情绪，不修改亲密度。

### 用户交互

- 单击：Happy 3 秒，亲密度增加 1。
- 1.5 秒内三击：Celebrate 4 秒。
- 同一窗口六击：Annoyed 5 秒，并进入 10 秒点击奖励冷却。
- 达到系统长按阈值：Happy 5 秒，亲密度增加 2，20 秒冷却。
- 轻度 IMU 动作：Curious 4 秒，3 秒事件冷却。
- 强烈撞击：Startled 3 秒，3 秒事件冷却。

## 非范围

- 不引入机器学习模型。
- 不在 V1 常驻开启麦克风；噪声互动留到功耗和音频抢占验证后。
- 不承诺计步和电量联动；当前项目没有稳定的业务快照接口。
- 不在本版本扩展手机端多素材上传协议。

## 资源与素材约束

- 行为模型仅使用固定大小结构，不进行动态内存分配。
- 每个状态 GIF 建议 160x160 或 192x192、10~12 FPS、2~4 秒。
- 单状态 GIF 建议不超过 180 KiB，完整状态包建议不超过 1 MiB。
- 状态 GIF 使用 `/pet/<state>.gif` 固定路径；缺失或损坏时回退到 `/pet.img`
  或内置 mascot。
- 任一时刻只允许一个 GIF 解码器和一套显示帧存在。

## 验收标准

- 固定事件脚本产生确定的状态序列，相同随机种子得到相同结果。
- 单击反馈不超过 250 ms，IMU 反馈不超过 350 ms。
- Agent Needs input/Error 覆盖不超过 300 ms，结束后恢复宠物情绪。
- 基础状态遵守最短驻留时间，点击、长按和 IMU 遵守冷却规则。
- RTC、IMU或状态 GIF 不可用时仍能正常显示 Calm 回退状态。
- 自主 GIF 播放时收到上位机 `PLAY(slot)`，300 ms 内切换到指定槽位且只保留一个
  GIF decoder；收到 `RESTORE` 后恢复当时有效的自主状态。
- 上位机打字开始/停止、蓝牙断开、远端槽位缺失四种路径均不会让自主状态机丢失，
  也不会遗留暂停的 GIF timer。
- 连续状态切换和页面进出无悬空 LVGL timer、对象或明显内存增长。
- 目标固件通过 `-Wall -Wextra -Werror` 编译，纯 C 行为模型通过主机测试。
