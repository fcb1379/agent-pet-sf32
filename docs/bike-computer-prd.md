# SF32 GPS 码表 MVP 产品需求文档

日期：2026-09-17

状态：已确认进入 X-TRACK 移植开发

## 1. 产品目标

在黄山派 SF32LB52 开发板上实现一个可户外骑行使用的 GPS 码表 MVP，验证新 GPS 转接板、实时骑行数据、触摸/按键交互、轨迹记录和低功耗基础能力。

MVP 不追求一次性覆盖离线地图、ANT+、训练计划或云同步。目标是先形成稳定、可测、可继续演进的产品骨架。

## 2. 目标硬件

- 主控板：黄山派 SF32LB52 V1.2。
- 构建目标：`sf32lb52-lchspi-ulp`。
- 显示：390 x 450，LVGL v8。
- 输入：触摸、按键。
- 定位：DX-GP10 GPS/BeiDou/GLONASS 模组及用户设计的转接板。
- 存储：板载 4 MiB 文件系统作为可靠回退；TF 卡用于长时间轨迹和离线地图，独立挂载且不自动格式化。
- 运动传感器：板载 LSM6DS3TR-C 与 MMC5603NJ，经 I2C2 提供 X-TRACK 计步、磁场和电子罗盘能力。

### 2.1 硬件门禁

DX-GP10 V2.0 数据手册（2024-06-18）已经确认以下内容：

- 模块主电源 2.7~3.4 V，推荐 3.3 V；供电能力至少 100 mA。
- UART 默认 9600 bps、8N1，输出 NMEA 0183；最大支持 115200 bps。
- TXD/RXD/1PPS/WAKE_UP 分别为模块 2/3/4/5 脚，RESET 实际为 9 脚。
- VCC_BACKUP 为 1.4~3.6 V，典型 3.3 V；不用时可以悬空。
- SET 悬空/高电平为 GPS+BeiDou，低电平上电为 GPS+GLONASS。
- 默认更新 1 Hz；双模最高 2 Hz，单模最高 5 Hz。
- 连续追踪典型电流约 22.5~24.4 mA，睡眠典型 20 uA。

手册表 3 将 RESET 误写为 8 脚，与引脚图和 2.6 节冲突；实现按后两处一致的 9 脚处理。立创 EDA 链接在未登录会话中仍不能读取，因此转接板到开发板的最终针脚映射、供电连接和天线安装仍需用导出的原理图/网表复核。

## 3. MVP 功能

### 3.1 定位与时间

- 显示定位状态、卫星数和最近一次有效定位年龄。
- 解析经纬度、海拔、地速、航向和 UTC。
- 首次有效定位后校准 RTC；时区独立配置，不修改原始 UTC 记录。
- GNSS 数据超时后明确显示失效，不沿用旧速度误导用户。

### 3.2 骑行状态

- 开始、暂停、继续、结束骑行。
- 当前速度、平均速度、最大速度。
- 总里程、移动时间、总经过时间。
- 当前海拔、航向、定位精度/状态。
- 自动暂停作为可配置功能，默认阈值在道路测试后确定。

### 3.3 界面

- 主数据页：速度为最大视觉元素，辅以里程、时间、平均速度。
- 定位页：坐标、海拔、航向、卫星、定位状态和时间。
- 骑行控制/总结页：开始、暂停、结束、保存/丢弃及本次统计。
- 390 x 450 布局；骑行中优先大字号、高对比、少触控区域。
- 按键必须能完成关键操作，避免手套或雨水导致只能依赖触摸。

### 3.4 轨迹记录

- 以 1 Hz 为默认采样频率记录有效定位点。
- 首版输出 GPX，保留时间、经纬度和海拔。
- 文件写入失败、空间不足和无定位必须可见且不得导致 UI 卡死。
- 断电或复位后能够识别未正常关闭的骑行文件，并安全关闭或标记为可恢复。
- 达到空间保留阈值后停止新记录，不能覆盖仍需保留的数据。

### 3.5 设置与持久化

- 单位：km/h 和 km。
- 时区。
- 轮径预留配置项，供后续 BLE CSC 使用。
- 自动暂停开关及阈值。
- 屏幕亮度/自动熄屏策略。
- 设置通过现有 FlashDB/产品设置层保存。
- 历史总里程、总时间、骑行次数和最高速度应使用可恢复双槽记录，骑行中定期异步检查点。

## 4. 第二阶段功能

- X-TRACK 离线瓦片地图、缩放和实时轨迹叠加。
- BLE 心率计，使用 SiFli HRPC。
- BLE 速度/踏频传感器，使用 SiFli CSCPC。
- BLE 功率计；先核对 SDK 是否有可直接使用的 Cycling Power Client。
- FIT 活动文件和断电修复。
- TF 卡长时间记录。
- 手机导航提示或 GPX 路线跟随。

## 5. 暂不纳入

- ANT+。
- 在线地图下载与云端瓦片服务。
- Strava 登录/上传。
- 室内骑行 FTMS 控制。
- 直接复制第三方完整 UI/框架。

## 6. 非功能要求

- GNSS、BLE、文件写入均不得在 ISR 或 LVGL 回调中长时间阻塞。
- UI 只能在 GUI 线程操作；外部数据通过固定容量快照/事件交付。
- 禁止 `malloc/free`、`new/delete` 和无界字符串。
- 所有文件名、缓冲区、队列和点数都有编译期上限。
- 所有设备操作、文件写入和线程创建必须检查返回值并向上报告。
- 记录任务必须有写入超时和错误降级策略。
- 资源报告区分 Flash、片内 SRAM、PSRAM 和文件系统剩余空间。

## 7. MVP 验收标准

### 7.1 构建验收

- `sf32lb52-lchspi-ulp` 全量构建通过。
- 无新增编译警告；`git diff --check` 通过。
- 输出 Flash、SRAM、PSRAM 增量。

### 7.2 台架验收

- 连续接收并解析 GNSS 数据 30 分钟，无溢出、死锁或 UI 卡顿。
- 模拟无效校验、断句、丢星、重连和数据超时，状态正确恢复。
- GPX 记录能被桌面工具打开，点数、时间和坐标单调合理。
- 记录过程中复位后，旧文件不阻止下一次骑行记录。

### 7.3 道路验收

- 与参考码表/手机对比至少一次 30 分钟路线。
- 速度、里程、移动时间和轨迹无明显异常跳变。
- 骑行中按键操作可完成开始、暂停和结束。
- 进行连续定位、屏幕策略和记录状态下的实际电流测量。

代码支持、构建成功、烧录成功、设备运行和道路/功耗验收必须分别报告，不能互相替代。

## 8. 已确认范围与剩余硬件输入

1. 已确认以 X-TRACK 为功能参考，移植骑行数据模型、GNSS 数据链路和 LVGL 码表交互，不搬运 Arduino/AT32 HAL、动态内存框架或原工程底层。
2. 首个可编译增量范围为“DX-GP10 NMEA + 骑行状态 + 单页主码表 UI”；GPX、三页面、BLE 传感器按后续阶段追加。
3. 待提供转接板导出的原理图 PDF、网表或关键页截图，以复核 PA20/PA27、供电、PPS、WAKE_UP 和 RESET 的实际连接。
4. RTC 自动校时、TF 卡 SPI1 存储、板载 LSM6DS3TR-C 计步和 MMC5603NJ 电子罗盘已纳入当前增量并完成源码/主机测试/目标构建验证；经典蓝牙音频保持模板现状，最终裁剪需结合整机资源与产品范围。
5. 计步和磁力计采用 QADSPI 屏幕配置下空闲的 PA39/PA40 作为 I2C2；切换到占用这两个引脚的 LCD 接口时必须重新完成资源评审，不能运行期强制复用。
